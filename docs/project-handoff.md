## 문제와 주요 판단

제품팀이 첫 학습 이후의 재방문 개선안을 검토하려면, 먼저 활동 기록의 의미와 분모를 믿을 수 있어야 한다. 원본의 반복 행을 모두 수집 오류로 단정하지 않고 처리 정책에 따라 판단이 어떻게 달라지는지 확인했다.

| 확인한 결과 | 의미와 한계 | 근거 |
|---|---|---|
| 적격 29,671건 중 첫 주 활성 23,522건, 그중 다음 주 활동 20,303건 → 86.3% | 재방문율 분모는 첫 주 활성 수강 건. 고유 사람 수·구독 유지율이 아님 | [분석 결과](../reports/findings.md), [지표 정의](data-contract.md) |
| 첫 주 1일 68.9%, 2일 이상 91.7% | 관찰 관계. 첫 주 활동일을 늘리면 재방문이 개선된다는 인과 결론은 아님 | [보고서](../reports/report.json) |
| 첫날 10클릭 충족 여부가 처리 정책에 따라 369건 변경 | 클릭 임계값을 확정적인 첫 학습 성공 기준으로 채택하는 안 보류. 실제 오류 369건이나 이탈 방지 369건이 아님 | 보고서 click_sensitivity |
| 첫날 콘텐츠 접촉의 전체 관찰 차이 약 +1.5%p, 22개 개설기 중 9개는 반대 방향 | 전체 평균만으로 콘텐츠 노출 확대를 결정하지 않음. 첫 주 활동일 비교와 다른 분석 | 보고서 content_comparison 및 cohorts |

첫 주 1일/2일/3일 이상을 나눈 최신 제출 SQL의 전체 분모·분자는 각각 **5,565/3,835**, **4,803/3,992**, **13,154/12,476**이다. 각 비율은 **68.9% / 83.1% / 94.8%**이며 2일 이상은 뒤의 두 그룹을 합산해 계산한다. 비율의 단순 평균을 사용하지 않는다.

실행 가능한 개선안은 다음 학습 진입 안내를 비교하는 조건부 실험 설계다. 실제 서비스 계측·이벤트 대조·적격성·관찰 기간을 확보한 뒤 검증해야 한다. 실제 CLASS101 실험이나 재방문·매출 개선 성과는 없다. [제품 판단](product-decision.md) · [실험 설계](experiment-plan.md).

## Codex가 수행한 일

- 공고·제품·자료·경쟁 포트폴리오·README 조사, 문제와 실험 설계의 초안 작성.
- 기존 생산 파이프라인·군집 부트스트랩·시기 분리·정책 민감도, 운영 연결과 이슈 이력, EdNet·생성 시나리오 구현.
- 기존 UI와 접근성 수정, 자동 테스트·독립 계산 대조·브라우저 검토·공개 배포.
- 사용자 실습·구현 계약 안내, 제출 코드의 원본 보존·검토·테스트 작성·실제 자료 재실행·문서 및 커밋 반영.

지원자 제출 코드와 Codex의 기존 생산 코드는 각각 근거를 가진다. 기존 기능이 이미 구현돼 있다는 사실과 그 기능을 지원자가 직접 작성했다는 주장을 구분한다. AI 호출 없이 핵심 분석·검사·데모가 작동한다.

## 검증과 수정의 근거

최근 집계 코드 검토에서 Codex의 52개 검사, 저장소 전체 **369개 테스트**, build/verify와 CI를 통과했다. 기본·strict 각각 69행 불일치0, 같은 입력 반복 JSON 일치. 앞선 분석표는 29,671행×12열 기존 SQL 대조와 3개 활동 지표의 별도 pandas 대조를 통과했다. 신규 제출 코드들은 검토에서 논리 수정 없이 보존됐다.

기존 개발 과정의 수정·실패는 [검증 기록](verification.md), [운영 v2](full-operations-v2.md), [사용성 피드백과 UI 수정](usability-results.md)에 남아 있다. 예를 들어 입력 오류 때 전체 회차를 다시 시작하던 부담을 바탕으로 Codex가 같은 입력에서 수정할 수 있는 v2를 구현했다. 이를 지원자가 코드를 수정한 경험으로 바꾸어 쓰지 않는다.

v2 사람 실측은 예정 6회 완료, 별도 본 측정 중단1회를 보존했다. A 3완료+1중단의 총 경과1,426.62초와 B 3완료의 총 경과356.57초는 해당 시도의 관측값이다. 코드 계산 시간·입력·검토가 섞이며 순서·학습 효과를 제거하지 못했다. 원본 전체 이벤트 로그를 Codex가 독립 감사한 것은 아니다. 일반적인 회사 생산성 절감률이나 v1→v2의 인과 효과로 환산하지 않는다.

보고서 SHA-256은 `675dfa6fa3126da0ba74b5a4b4c4222afff4d950297703f3314788f9135a30db`다. 이번 정리는 기존 검증 근거를 모은 문서 작업이며 모든 브라우저·실제 기기 검사를 새로 실행했다는 뜻은 아니다.

## 사실대로 사용할 표현과 피할 표현

## 재현과 다음 작업

이미 완료한 실습을 다시 해야 하는 목록이 아니다. 필요할 때 확인할 경로다.

1. 데모의 **지표 검토 → 동일 값 반복 → 지표 영향**에서 정책별369건을 확인한다.
2. **재방문 근거**에서 분모와 전체·개설기별 결과를 본다. 콘텐츠 접촉 비교와 활동일 비교를 구분한다.
3. 본인 제출 코드는 `evidence/applicant/`와 각 검토 문서의 실행 방법을 따른다. [분석표 실행](applicant-mart.md#재현), [집계 실행](applicant-aggregate.md#실행-방법).
4. 전체 로컬 테스트는 설치된 프로젝트 환경에서 `python -m pytest -q`, 결과 일치는 `python scripts/build.py` 후 `python scripts/verify.py`로 확인한다. 설치 여부나 파일 경로가 확인되지 않은 장치에서 성공을 가정하지 않는다.

현재는 이 문서와 근거를 바탕으로 제출용 포트폴리오·자소서를 별도로 작성할 수 있다. 그 원고 작성은 최초 요청에 따라 이번 정리 범위에 포함하지 않았다. 이 정리 당시 전체 재구현은 지원 준비의 필수 보완 목록에 두지 않았다. 이후 사용자가 선택한 2026-11-06 후속 구현의 범위와 역할은 문서 맨 위 계획에 고정했다.

CLASS101 내부 접근·실제 서비스 A/B 효과, 실제 갱신/매출 결과, 공개 자료의 원천 누락, 모든 기기의 접근성 적합성, 프로젝트 전체의 본인 독립 작성은 확인한 사실이 아니다. 이 한계를 없애기 위해 근거 없는 완료 표시나 추가 사람 실측을 요구하지 않는다.
