## 코드에서 확인한 판단

- 반복 그룹마다 `행 수 - 1`을 합산하므로 동일 행 3개는 초과 2개다. 반복 그룹이 없을 때는 `COALESCE`로 NULL 대신 0을 반환한다.
- 여섯 열을 모두 묶는다. 클릭 수만 다른 행을 동일 값 반복으로 세지 않는다. 이는 일별 복합키 반복과 다른 정의다.
- 미등록 활동은 `NOT EXISTS`로 등록 존재 여부를 확인한다. 등록의 동일 키가 여러 행이어도 활동 건수가 늘어나지 않는다.
- `id_student IS NOT NULL` 조건은 요구사항대로 적용했다. 학습자 키 결측을 통과한 정상 자료라고 판정한 것은 아니며 필수키 결측 검사는 별도 규칙이다.
- 마지막 SELECT가 `rule_id`, `issue_count` 두 열의 세 행을 고정 순서로 반환한다.

위 설명은 Codex가 코드를 읽고 확인한 내용이다. 지원자가 별도로 설명한 발언으로 기록하지 않는다.

## 손계산 가능한 검사

Codex가 만든 16개 검사는 빈 테이블에서 세 건수 모두 0, 동일 행 1/2/3/5개에서 초과 0/1/2/4, 여섯 열 각각의 값 변화, 여러 반복 그룹의 합산, 등록일 0·음수·NULL 구분을 포함한다.

등록 2행이 같은 학습자 키이고 그중 등록일 결측이 1행인 사례에서, 해당 학습자의 정상 활동 1행과 미등록 학습자의 동일 활동 2행을 넣었다. 기대값은 **등록일 결측 1 / 반복 초과 1 / 미등록 활동 2**이며 제출 SQL이 일치했다. 미등록 활동의 반복도 원본 활동 행 수대로 센다.

학습자 ID NULL인 동일 활동 2행은 반복 초과 1 / 미등록 활동 0으로 처리했다. 강좌 키가 NULL이면 SQL의 등호 비교로 등록과 일치하지 않는 경우도 확인했다. 각 사례에서 SQL을 두 번 실행하고 입력 행이 보존되는지 대조했다. 작은 사례는 Codex의 가상 시험 자료이며 실제 학습자 데이터나 지원자가 만든 사례가 아니다.
