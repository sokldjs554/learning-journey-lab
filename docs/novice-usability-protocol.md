# 처음 보는 사람의 데모 이해도 확인

현재 상태: **과제와 빈 기록 양식 준비. 2026-10-30 진행자가 참여자 1명의 참여 가능·익명 기록 동의를 확인했다고 보고했다. 과제 수행 결과는 아직 받지 않았다.** 개발자의 Playwright 조작·접근성 검사는 실제 사용자 이해도나 피드백을 대신하지 않는다. 가상의 참여자·발언·성공률은 기록하지 않는다. 다음 검증은 사용성 확인이며 리텐션·매출 개선 실험이 아니다.

진행자는 프로젝트를 처음 보는 참여자(지원자 본인이라면 기존 경험을 명시)에게 데모 주소와 아래 과제만 준다. 정답이나 이동 경로를 먼저 설명하지 않는다. 관찰과 인용에 동의한 범위만 기록하며 실명·연락처는 필요하지 않다. 한 과제에 오래 막히면 참여자가 중단을 선택할 수 있다. 진행 중 도움을 주었다면 도움을 준 시점과 내용을 남기고 독립 수행과 구분한다.

| 과제 | 참여자에게 읽어줄 문장 | 진행자 확인 기준 |
|---|---|---|
| 1. 문제 찾기 | 이 프로젝트가 어떤 문제를 확인하려는지, 화면의 근거 한 곳과 함께 설명해 주세요. | 학습 재방문 지표를 로그 품질·정의와 함께 검토한다는 취지를 찾는지. 실제 서비스 운영 화면으로 오해하는지. |
| 2. 369건 해석 | 반복 행 처리에 따라 바뀐다는 369건은 무엇인지 찾아 설명해 주세요. | 첫 주 활성 수강 건 중 첫 활동일 클릭이 10회 이상인 수강 건의 분류가 달라짐을 구분하는지. 369명의 순수 사용자나 삭제된 로그 행 수로 오해하는지. |
| 3. 판단과 반대 근거 | 재방문 분석을 보고 어떤 판단을 했는지, 그 판단을 조심해야 하는 근거도 찾아 주세요. | 전체 관찰 결과, 개설기별 방향 차이/반대 근거, 인과 효과 미확정을 찾는지. |
| 4. 다음 검증 구분 | 다음에 무엇을 실험하려는지와 아직 실제로 검증하지 않은 것을 구분해 주세요. | 제안/설계와 실행 결과, 실제 사용자 검증·리텐션/매출 효과 미확정을 구분하는지. |

각 과제 후 “무엇이 이해하기 어려웠나요?”를 묻고 실제 답변만 인용한다. 참여자의 말과 진행자의 해석을 나눈다. 성공/도움 후 성공/미완료는 실제 행동이 관찰되었을 때만 선택한다. 문제를 고쳤다면 어떤 화면·설명을 바꿨는지와 재검토 대상·날짜·동일 참여자인지 기록한다. 수정했다고 이해도 향상을 자동 추정하지 않는다.
