# 학습 신호와 갱신을 연결하는 계약

**100% 생성 데이터, Codex 구현·검증. 실제 CLASS101/OULAD/EdNet 구독 성과가 아니다.** 공개 분석으로 구독 갱신을 추정하지 않고, 내부 데이터가 제공된다면 어떤 단위와 시간 조건으로 연결해야 하는지를 실행 가능한 SQL로 보완했다.

## 왜 계정을 바로 결제에 연결하면 안 되는가

그룹 구독에서는 결제자와 학습자가 다르다. 구성원 활동 2행을 결제 1행에 직접 JOIN하면 결제가 2건처럼 늘어날 수 있다. 갱신일까지 도달하지 않은 연간 계약을 실패로 세면 분모도 틀린다. 카드 할부, 결제 실패, 해지 요청, 전액 환불은 각각 구분해야 한다.

이번 SQL은 **구독 갱신 주기 1행**을 기준으로 학습을 먼저 집계하고 결제를 별도 집계한 뒤 결합한다. `cycle_id` 외에 `(subscription_id, renewal_due_at)` 중복도 차단한다. 학습자 수와 결제자 수를 합산하지 않는다.

## 최소 원장

| 테이블 | 핵심 키·시각 | 사용하는 이유 |
|---|---|---|
| cycles | cycle_id, subscription_id, payer_id, plan_type, started_at, renewal_due_at, cancel_requested_at | 갱신 기회와 결제 주체 정의. 해지 요청만으로 분모를 제거하지 않음 |
| members | cycle_id, learner_id, valid_from, valid_to | 활동 당시의 그룹 소속 확인. 현재 구성원 목록을 과거 전체에 붙이지 않음 |
| learning | event_id, cycle_id, learner_id, occurred_at, ingested_at | 첫 7일 활동과 수신 시점을 분리. 유효 학습 판정은 상류 계약 |
| billing | event_id, transaction_id, cycle_id, kind, occurred_at, ingested_at | 결제 성공·실패·전액 환불을 분리하고 중복 수신을 제거 |

동일 ID·동일 행 재전송은 한 번 처리하지만 내용이 다르면 차단한다. OULAD는 원천 이벤트 ID가 없으므로 이 정책을 OULAD에 소급 적용하지 않는다. 중복/충돌 키, 겹치는 소속 구간, 소속 없는 학습, 정산 없는 환불, 역전 시각은 통과시키지 않는다.

## 지표 계약

- 모든 시각은 UTC로 정규화한다. `as_of`는 수신 cutoff, `watermark`는 그 시각 미만의 원천 수집이 완료됐다는 **이 예제의 명시적 가정**이다. 회사에서 이러한 보증이 실제로 성립하는지는 별도 대조해야 한다.
- 첫 학습 신호: `[started_at, started_at+7일)` 안의 고유 UTC 활동 날짜 수. 그룹은 구성원들의 날짜 합집합이며 개인의 활동일과 동일한 의미가 아니다. 해당 창이 미성숙하면 NULL이다.
- 가상 갱신 처리 창: `[renewal_due_at, renewal_due_at+7일)`. **7일은 검증용 선택이며 회사의 청구/유예 정책이 아니다.** 마지막 경계의 결제는 이 창에 포함하지 않는다.
- 분모: 처리 창 전체가 `as_of`와 `watermark` 모두에서 지난 주기. 미성숙은 `pending`, `renewed=NULL`로 두며 0으로 채우지 않는다.
- 분자: 그 창에서 성공한 거래가 있고, 보고 시점까지 관측된 전액 환불로 모두 상쇄되지 않은 주기. 비율은 분자/성숙 분모이고 0분모는 NULL이다.
- 상태 우선순위: 미성숙 → 갱신 → 전액 환불 → 결제 실패 → 창 내 정산 없음. 마지막 두 상태를 모두 자발적 이탈로 부르지 않는다. 창 이후 결제는 원천에 남지만 고정 창의 성공으로 소급하지 않는다.
- 보고 시점 이후 수신 행을 분자에 넣지 않는다. 이미 완료 보증한 시각의 알려진 미수신 행은 watermark 모순으로 차단한다.

## 손으로 확인 가능한 생성 사례

생성기는 `src/journey/subscription_bridge.py::fixture`의 고정 목록이다. 난수·외부 API·실제 고객 ID를 사용하지 않는다. `data/synthetic/subscription_bridge.json`과 `reports/subscription-bridge.json`은 재생성 가능한 산출물이다.

| 가상 주기 | 일부러 만든 상황 | 결과 |
|---|---|---|
| c1 | 정상 결제, 첫 주 2일 활동 | 갱신 1 |
| c2 | 결제 실패만 수신 | 갱신 0, 결제 실패 |
| c3 | 결제 후 전액 환불 | 갱신 0, 전액 환불 |
| c4 | 다음 갱신일이 아직 미래 | 미성숙, 분모 제외 |
| c5 | 그룹 학습자 2명·서로 다른 날짜, 동일 결제 재전송 | 학습일 2일, 갱신은 1건 |
| c6 | 해지 요청 이력 후 성공 결제 | 요청만으로 제외하지 않고 갱신 1 |
| c7 | 해지 요청, 창 내 정산 없음 | 갱신 0, 원인은 미확정 |
| c8 | 가상 7일 창 밖에서 성공 결제 | 창 내 갱신 0; 영구 이탈이라고 단정하지 않음 |

손계산: 8주기−미성숙 1=분모 7, c1·c5·c6=분자 3. **3/7은 검증 예제의 값으로 실제 유지율이나 성과가 아니다.**

## 사업 판단으로 이어가기 위한 조건

이 장부는 조인·분모·시점 처리만 검증한다. 실제로는 갱신 예정 전체 모집단, 플랜 변경/일시정지/선결제, 부분 환불, 결제·청구 금액과 통화, 계약·권한 변경 이력, 콘텐츠 이용 가능 기간, 수집 완전성을 추가해야 한다. 모든 실제 billing 케이스를 지원하는 엔진이 아니다. 매출 인식·이익·LTV를 산출하지 않는다.

권한 있는 원장이 생기면 첫 주 관찰이 끝난 동일 기준점에서 후보 신호를 고정하고 이후 갱신을 추적한다. 미래 활동이 있는 사람만 남기지 않으며, 갱신일까지 관찰된 코호트와 미성숙 코호트를 구분한다. 개인/그룹·플랜·유입·가입 시기의 차이와 학습 의지에 의한 교란을 검토한다. 예측력이 다른 시기에서도 유지되는지 확인하더라도 인과 효과가 증명되는 것은 아니다. 최종적으로 해당 행동을 바꾸는 실험과 장기 갱신 결과를 함께 추적해야 한다.
