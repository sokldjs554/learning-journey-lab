# EdNet-KT4: 실제 공개 로그로 수행한 보조 관찰 분석

**첫 관측 주에 문제 묶음을 제출한 24시간 구간이 1개인 사람과 2개 이상인 사람 사이에 이후 제출 기록의 차이가 있었다. 이 차이는 실험 효과·구독 유지율이 아니다.** OULAD의 분석·결과는 변경하지 않았고, 실제 Santa 로그를 별도로 확보해 질문과 이벤트 정의를 검증했다.

## 데이터와 표본

원출처: [Riiid EdNet](https://github.com/riiid/ednet), [논문](https://arxiv.org/abs/1912.03072), CC BY-NC 4.0 연구용 공개 데이터. 후보 비교와 이용 조건은 [데이터 조사](data-sources.md), 기계 판독 결과는 [ednet_report.json](../reports/ednet_report.json)에 있다.

공식 KT4 ZIP에 포함된 이용자 파일 297,915개에서 파일명만으로 2,048개를 선정했다. `SHA256("learning-journey-lab-ednet-kt4-v1:" + ZIP 내부 파일명)`이 작은 순서이며 행동량·결제·이후 방문 여부를 선택에 사용하지 않았다. 선택된 이용자의 전체 기록을 내려받았으므로 각 파일의 처음 몇 행을 잘라낸 표본이 아니다. 확보한 원본은 **854,678행, 39,501,752바이트**다. ZIP 전체 1.17GB를 받는 대신 중앙 색인과 선택 파일의 바이트 범위를 받아 KT4 네트워크 전송은 161,649,539바이트였다. 콘텐츠 ZIP은 173,976바이트다.

ZIP CRC와 사용자 파일별 SHA-256을 확인했고, 선택 목록의 SHA-256은 `7171342decf5a0f0a0567e63e19543bd109919dfc26ab6750a40780ce7b5b958`, 정렬된 파일·해시·크기 목록의 SHA-256은 `ad82186e6bcd27a11f4533ff1b89e6b17a4beda1deb0b65ca88f6da324103007`이다. 전체 ZIP을 받지 않았으므로 전체 ZIP의 SHA-256을 검증했다고 쓰지 않는다. 원본·사용자별 해시 목록은 `.gitignore`의 `data/raw/` 아래에만 둔다.

## 질문과 지표

질문은 “처음 기록된 활동 이후 첫 7일의 활동 구간 수와 그다음 7일에 기록된 학습 활동 사이에 어떤 연관이 있는가?”다. 실제 신규 가입일이 없으므로 **신규 이용자 코호트**라고 부르지 않는다.

- 기준 시점: 이용자 파일의 첫 기록 시각. 가입일이나 첫 학습일이라는 보장은 없다.
- 첫 구간: 기준 시점부터 `[0, 7×24시간)`.
- 다음 구간: `[7×24시간, 14×24시간)`. 정확히 7일 경계는 다음 구간, 14일 경계는 분석 밖이다.
- 활성 구간: `floor((timestamp - 첫 기록 timestamp)/86,400,000)`. 이동된 시각의 달력 날짜를 실제 서비스 날짜처럼 쓰지 않기 위해 **달력 날짜가 아닌 경과 24시간 구간**을 쓴다.
- 주 활동: `action_type='submit'`이면서 `item_id`가 문제 묶음(`b`+숫자). 최종 답 제출 기록이지 문제 하나, 콘텐츠 수료, OULAD의 클릭 합계가 아니다.
- 분모: 첫 구간에 이 활동이 한 번 이상 있는 2,030명. 18명은 제출 기록이 없어 제외했다. 분모에 다음 구간 활동이나 마지막 활동일 조건을 넣지 않았다.
- 분자: 다음 구간에 같은 활동이 한 번 이상 기록된 사람.

## 실제 결과

| 첫 구간의 제출 활성 구간 수 | 다음 구간 제출 기록 / 분모 | 기록 비율 | Wilson 95% 구간 |
|---|---:|---:|---:|
| 정확히 1개 | 31 / 1,688 | 1.84% | 1.30–2.59% |
| 2개 이상 | 135 / 342 | 39.47% | 34.44–44.74% |

차이는 **+37.64%p**, 이용자 단위 2,000회 부트스트랩(seed=101)의 95% 구간은 **+32.13~+42.86%p**다. 이 구간은 표본 변동만 나타낸다. 관측 종료, 숨은 동기·숙련도, 무료/유료 이용 조건, 추천 노출, CLASS101로의 이전 가능성은 보정하지 못한다.

처음 주의 반복 학습이 이후 기록과 관련된다는 탐색 근거는 생겼다. 그러나 반복 학습을 시키면 그만큼 리텐션이 오른다거나 재개 화면의 개선 효과라고 해석할 수 없다. 실험 처치·무작위 배정·실제 참여자 모집은 수행하지 않았다. 사용자 요청의 **B: 공개 데이터 기반 과거 관찰 검증**을 수행한 것이다.

## 이벤트 정의와 품질이 바꾸는 것

| 활동 정의 | 첫 구간 활동 분모 | 1개 구간: 다음 기록 / 분모 | 2개 이상 구간: 다음 기록 / 분모 |
|---|---:|---:|---:|
| 문제 묶음 최종 제출 `submit b…` | 2,030 | 31 / 1,688 | 135 / 342 |
| 학습 화면 진입 `enter b/e/l…` | 2,037 | 36 / 1,683 | 142 / 354 |
| 모든 UI·결제·쿠폰 이벤트 | 2,048 | 35 / 1,683 | 149 / 365 |

모든 기록을 학습 활동으로 세면 첫 구간 2개 이상 여부가 **23명**, 다음 구간 기록 여부가 **14명** 바뀐다(전체 2,048명 비교). 첫 구간 제출이 없던 18명도 분모에 추가된다. 결제·쿠폰과 오디오 조작은 학습 제출과 같은 의미가 아니므로 운영 지표에 행동 계약을 명시해야 한다.

원본의 완전히 같은 행은 **1,519개**였다. 원본 854,678행에서 중복 제외 시 853,159행이 되지만 활성 구간 수·다음 구간 플래그가 바뀌는 사람은 **0명**이었다. 원본에 유일한 이벤트 ID가 없어 같은 행만 보고 전송 중복인지 실제 반복 행동인지 확정할 수 없다. 따라서 주 분석은 원본을 유지하고 제거 결과를 민감도 점검으로만 썼다. OULAD의 일별 집계 반복 행과 원인이 같다고 추정하지 않는다.

실제 발견한 정합성 문제도 처리했다. 공식 README는 결제 카탈로그 필드를 `payment_type,duration`으로 설명하지만 파일은 `type,duaration`이었다. 첫 실행은 스키마 불일치에서 중단했고, 원본 필드를 보고 명시적 이름 매핑을 추가해 재실행했다. 이 매핑과 잘못된 결제 키/중복 카탈로그 키의 검증을 테스트로 남겼다. 플랫폼 공란 **184행**은 `pay 173 + refund 5 + enroll_coupon 6`에만 있었다. 이를 학습 화면의 플랫폼 수집 실패 184건이라고 부르지 않는다. 알려지지 않은 비공란 플랫폼 값은 0건이었다.

## 실제 결제 기록으로 확인한 범위

표본의 각 이용자 전체 기록에서 `pay` **173행 / 164명**, `refund` **5행 / 5명**, `enroll_coupon` **6행 / 5명**을 확인했다. 관측된 결제·환불은 모두 카탈로그의 `pass`에 연결됐고 알 수 없는 결제 키는 0개였다. 카탈로그 전체에는 `pass`, `paygo`와 미상 값 `-1`이 있다.

이 수치는 기간이 다른 전체 이력의 이벤트 개수다. **164/2,048을 동일 관측기간의 전환율이라고 부르지 않는다.** 결제 가격·통화·유일 거래 ID·권한 원장·자동 갱신 상태가 없고 반복 결제가 새 상품 구매인지 갱신인지도 구분하지 못한다. 매출, 순매출, 갱신율, 구독 이탈률은 계산하지 않았다. 173−5를 순매출/유효 이용권 수로 쓰지 않는다.

## 관측 종료와 반대 점검

가장 큰 남은 한계는 이용자별 관측 종료 메타데이터가 없다는 점이다. 2,048명 중 14일 이후 어떤 기록이라도 있는 사람은 287명이고, 나머지 1,761명에서 활동 중단과 데이터 수집 종료를 구분할 수 없다. 서로 이동된 시각의 최댓값을 공통 서비스 종료일로 간주하지 않았다. 개인 마지막 활동일이 14일 뒤인 사람만 포함하면 미래 행동으로 분모를 선택하는 오류가 생긴다.

이 잘못된 선택이 얼마나 큰 차이를 만드는지 **진단용으로만** 따로 계산했다. 미래 기록이 있는 287명 중 첫 구간 제출이 있는 275명으로 제한하면 1개 구간 집단은 16/96=16.67%, 2개 이상 집단은 111/179=62.01%가 된다. 이는 관측 종료를 해결한 보정 추정치가 아니라 **미래 선택·생존자 편향이 들어간 비교**다. 주 결과와 나란히 확인하고, 배포 데모의 대표 지표로 대체하지 않는다.

따라서 결과 명칭은 “다음 구간 제출 **기록 비율**”로 제한한다. 기록이 없다는 사실을 확인된 이탈로 바꾸지 않는다. 현재 데이터로는 관측 종료를 해결한 리텐션 추정이나 재개 화면 인과 효과를 식별할 수 없다.

## 재현과 검증

저장소 루트에서 기존 의존성을 설치한 환경으로 실행한다. 외부 다운로드는 일반 테스트/CI에서 자동 실행하지 않는다.

```bash
python scripts/download_ednet.py --output data/raw/ednet --users 2048
PYTHONPATH=src python -m journey.ednet --raw data/raw/ednet --output reports/ednet_report.json
python -m pytest tests/test_ednet.py tests/test_ednet_download.py -q
```

기본 실행은 버전 관리하는 [고정 스냅샷](../data/ednet_snapshot.json)의 표본 크기·seed·ZIP 색인·선정 목록·원본 파일 묶음·콘텐츠 ZIP 해시와 대조한다. 단순히 이번 다운로드에서 만든 해시끼리 비교하지 않는다. 크기나 seed 변경은 다른 분석이므로 별도로 검토한 스냅샷 없이 실행되지 않는다. 정상 캐시는 전체 파일을 검증한 뒤 네트워크 없이 재사용한다. 오염·불완전 캐시는 덮어쓰지 않고 중단한다. 새 다운로드는 임시 디렉터리에서 기준 해시를 모두 검증한 뒤에만 최종 경로로 옮긴다. 다운로드 실패는 실패로 보고하며 생성 데이터로 대체하지 않는다. Google Drive가 범위 요청을 지원하지 않거나 파일이 이동하면 다운로드가 명시적으로 실패한다. 원출처 파일이나 ZIP 색인이 기준에서 바뀌어도 자동으로 새 기준을 채택하지 않는다. 다운로드 시각과 전송량은 로컬 감사 manifest에만 남기고 공개 집계 manifest에서 제외하므로, 같은 원본을 다른 날 확보해도 분석 결과 바이트가 달라지지 않는다. 공개 manifest에는 실제 사용자 파일명/목록을 넣지 않고 seed와 해시만 남긴다.

[SQL](../sql/ednet.sql)과 별도로 작성한 [pandas 계산](../src/journey/ednet.py)을 전체 2,048명·10개 열에서 비교했다. 날짜 경계·반복 행·첫 구간 무활동·빈 분모·결측/잘못된 시각·잘못된 사용자 키·카탈로그 불일치·ZIP CRC 등을 테스트했다. 반복 실행의 집계 일관성과 파일 해시 검증은 [검증 기록](../reports/ednet_verification.json)에 남긴다. 실사용자 피드백이나 CLASS101 실험 성공을 의미하는 검증은 아니다.

## 제품팀에서 쓸 수 있는 다음 행동

이 분석은 재개 기능 효과를 주장하는 근거가 아니라 측정 계약을 구체화하는 근거다. 실제 검증 전에는 `screen_resume_view`, `lesson_start`, `lesson_progress`, `lesson_complete`를 구분하고, 결제/쿠폰은 학습 활동 분자에서 분리해야 한다. 사용자별 노출 시작·관측 가능 종료·배정·기기·유일 이벤트 ID와 재시도 중복 정책을 확보한 뒤 실험한다. 유료 유지나 매출은 별도의 권한/거래/환불 원장과 가격·통화·갱신 상태가 준비되어야 정의할 수 있다.
