# 전체·개설기별 활동 집계: 제출 전 계약

2026-11-05 두 파일의 [제출·기능 검토를 완료](applicant-aggregate.md)했다. 아래는 제출 전에 고정한 요구사항을 보존한 것이다.

2026-11-05. 원본 검증·적재·품질 검사·분석표 생성의 제출·기능 검토는 완료했다. 이번에는 `build_mart.py`가 만든 CSV를 읽어 **전체와 개설기별 활동 그룹의 분자·분모·비율을 저장**한다. 지원자의 기존 [1일·2일·3일 이상 SQL](../evidence/applicant/activity-threshold.sql)을 재사용한다. 완료한 실습·실측을 다시 수행하는 과제가 아니다.

Codex가 정리한 구현 요구사항이다. 요구사항을 작성한 시점에는 집계 모듈 제출 전이었으며, 후속 완료 근거는 위 검토 문서를 따른다. 아래 파일 이름과 결과 형식은 기존 모듈과 연결하기 위한 선택이며, 완성 구현 코드는 제공하지 않는다.

## 이번 제출 파일과 작업 위치

직접 구현 중인 폴더에서 아래 두 파일을 작성한다. 기존 `build_mart.sql`, `build_mart.py`, 원본 CSV는 보존한다.

| 파일 | 역할 |
|---|---|
| `aggregate.sql` | `mart` 테이블을 읽어 전체·개설기별 집계 결과를 반환하는 SELECT |
| `run_aggregate.py` | CSV 읽기·형식 검증 → 메모리 DuckDB의 mart → SQL 실행 → 집계 JSON 저장 |

제출한 `build_mart.py`는 **원본 수강 건을 만드는 코드**, 이번 코드는 **그 수강 건을 묶어 결과를 만드는 코드**다. DB 재적재나 전체 품질 SQL 재작성이 필요하지 않다. CSV 형식 검증이 원천 로그 품질·완전성 검사까지 대신한다는 표현은 사용하지 않는다.

## SQL 입력과 결과

입력 `mart`는 [직전 분석표의 12개 열](applicant-mart-spec.md)을 갖는다. 수강 건 키는 `(code_module, code_presentation, id_student)`이며 사람 수와 수강 건수를 혼동하지 않는다. 같은 사람이 다른 강좌를 수강한 행은 별개의 수강 건이다.

첫 주 활동 그룹은 `1일`, `2일`, `3일 이상`의 세 가지다. `w1_days=0`은 이 세 그룹의 분모에서 제외한다. 전체 집계는 모든 적격 수강 건을 입력으로 삼고, 개설기 집계는 `code_module`과 `code_presentation` 두 열로 나눈다.

다음 7열을 반환한다.

| 열 | 정의 |
|---|---|
| scope | 전체는 `overall`, 개설기별은 `cohort` |
| code_module | 전체 행은 NULL, 개설기 행은 원본 값 |
| code_presentation | 전체 행은 NULL, 개설기 행은 원본 값 |
| activity_group | `1일`, `2일`, `3일 이상` |
| denominator | 해당 범위·그룹의 수강 건수 |
| numerator | 해당 범위·그룹 중 w2_active=1인 수강 건수 |
| return_rate_pct | 100 × numerator ÷ denominator, 소수 첫째 자리 반올림. 분모 0이면 NULL |

전체 3행을 먼저 내보내고, 이후 강좌·개설기 키 순서로 각 3행을 내보낸다. 그룹은 1일→2일→3일 이상 순서다. **입력에 존재하는 개설기**마다 세 그룹을 모두 출력하고, 없는 그룹은 분모0·분자0·비율NULL로 표시한다. 첫 주 활동이 전혀 없는 개설기도 입력에 수강 건이 있으면 남긴다. 헤더만 있는 빈 입력은 전체의 빈 그룹 3행만 출력한다.

현재 기본 OULAD는 22개 개설기이므로 `(1+22)×3 = 69행`이다. 개설기 수나 결과값을 SQL에 고정하지 않는다.

## Python 연결

명령행 입력은 `--mart`(CSV), `--sql`(aggregate.sql), `--output`(JSON)이다.

1. CSV를 읽고 이전 12열 계약을 확인한다. 필수 키 결측·중복, w1_days 범위 밖, 0/1이 아닌 활동값, 첫 주 비활성 값의 모순 등을 오류로 처리한다. 앞선 제출 `build_mart.py`의 검증 함수를 재사용해도 된다. NULL 가능한 first_day/date_unregistration은 빈 CSV 값을 NULL로 처리한다. 정상 빈 파일은 헤더가 있는 0행 입력이며, 헤더조차 없는 파일과 구분한다.
2. CSV를 메모리 DuckDB의 `mart`에 올리고 SQL을 실행한다. DB 파일·원본 CSV를 수정하지 않는다. 입력 순서는 바뀌어도 같은 결과가 나오도록 정렬하거나 키 중복을 별도로 검사한다.
3. 결과의 열·범위·그룹·키 조합, 중복/누락, 정수 건수, `0 ≤ numerator ≤ denominator`, 비율 계산을 검증한다. 전체 3그룹 합계와 개설기별 그룹 합계가 아래 overall의 첫 주 활성·재방문 건수와 일치해야 한다. 반올림 비율을 평균내 전체 비율을 만들지 않는다.
4. 아래 JSON을 저장한다. 출력은 집계만 포함하고 id_student 목록을 내보내지 않는다. 같은 CSV·SQL이면 JSON 바이트도 같게 한다. 현재 시각·실행 시간은 이 결정적 결과 파일에 넣지 않는다.
5. 정상 종료 0, 입력·SQL·결과·저장 오류는 1. 실패하면 기존 결과 파일을 유지하고 임시 파일을 정리한다. 입력 CSV/SQL을 출력 경로로 덮어쓰지 않는다. 이 모듈에 원천 품질 gate PASS/REVIEW/BLOCK을 새로 꾸며 붙이지 않는다.

JSON 최상위 구조:

- `schema_version`: 1
- `scope`: `descriptive_activity_groups`
- `input_sha256`: 입력 CSV 원본 바이트의 SHA-256
- `overall`: `eligible`, `w1_active`, `w2_returned`, `return_rate_pct`
- `rows`: SQL 결과 69행(현재 실제 자료 기준)의 7열을 객체로 저장한 배열

`eligible`은 CSV의 전체 수강 건수, `w1_active`는 w1_days≥1 건수, `w2_returned`는 그중 w2_active=1 건수다. overall.return_rate_pct도 w2_returned / w1_active ×100이며 분모0은 NULL이다. 0일 활동군의 다음 주 활동을 여기에 더하지 않는다. `rows`는 전체 행과 개설기 행이 겹치므로 전부 더하면 이중 계산된다는 점에 주의한다.

## 실제 기본 정책의 대조 기준

전체: 적격 **29,671**, 첫 주 활성 **23,522**, 그중 다음 주 활동 **20,303**, 비율 **86.3%**.

| 범위 | 활동 그룹 | 분모 | 분자 | 비율 |
|---|---|---:|---:|---:|
| 전체 | 1일 | 5,565 | 3,835 | 68.9% |
| 전체 | 2일 | 4,803 | 3,992 | 83.1% |
| 전체 | 3일 이상 | 13,154 | 12,476 | 94.8% |
| BBB·2014J | 1일 | 484 | 330 | 68.2% |
| BBB·2014J | 2일 | 435 | 340 | 78.2% |
| BBB·2014J | 3일 이상 | 551 | 494 | 89.7% |

[69행의 전체 대조 자료](../reports/applicant-aggregate-reference.json)는 Codex가 기존 기본 정책 분석표에서 Python csv로 계산했다. 지원자의 새 구현 결과가 아니며 정답을 상수로 반환하는 데 사용하지 않는다. 대조 파일의 prepared_by/status/policy/source/calculation은 Codex의 출처 설명이며 제출 JSON의 필수 필드가 아니다. input_sha256은 실제 입력 바이트에 따라 달라지므로 CSV 줄바꿈·직렬화가 다르면 참고 파일의 해시와 일치하지 않을 수 있다. 본인 실행은 실제 입력 해시를 기록하고 집계값을 비교한다. strict CSV를 넣었을 때도 입력에 따라 집계하되 기본 정책의 고정 숫자와 같아야 한다고 검사하지 않는다.

## 작은 예시와 검토 기준

이미 손계산을 완료한 [가상 8행](../evidence/applicant/activity-threshold-fixture.csv)의 핵심 값은 재사용한다. 이 파일은 3열 교육 예시이므로 12열 CSV 실행에 그대로 넣지는 않는다. Codex가 제출 후 분석표 형식으로 변환해 테스트한다. 다시 손계산 답변을 제출할 필요는 없다.

같은 개설기 8건일 때 1일은 2/1/50.0%, 2일은 2/1/50.0%, 3일 이상은 3/2/66.7%이며, 전체 첫 주 활성은7건·재방문4건·57.1%다. 표기는 분모/분자/비율 순서다.

Codex는 다음 실패 가능성을 검토한다: 빈 입력·빈 그룹·0일 활동 제외, 같은 사람의 여러 수강 건, 개설기 복합키, 전체/개설기 합계, NULL과 잘못된 입력, 반올림, 실패 시 기존 JSON 보존, 반복 실행. 실제 기본·strict 분석표와 독립 집계도 대조한다.

## 실행과 제출

**두 파일을 작성한 뒤** 직접 구현 폴더에서 실행하는 명령 예시다. Python 환경에 DuckDB가 설치되어 있어야 한다.

```bash
python run_aggregate.py --mart work/applicant/mart.csv --sql aggregate.sql --output work/applicant/activity-groups.json
```

`--mart`는 본인 장치에서 실제 생성한 CSV 경로로 바꾼다. 예시 경로의 존재를 가정하지 않는다. 아직 CSV가 없으면 이전 제출 파일로 만드는 방법은 [분석표 재현 안내](applicant-mart.md#재현)에 있다.

완성한 `aggregate.sql`, `run_aggregate.py`와 사용한 참고·도움 범위를 보내면 된다. 실행했다면 전체 집계 출력도 보낼 수 있으며, 전체 학습자 CSV는 보내거나 공개하지 않는다. 파일 제출 뒤 Codex가 실제로 검토한 범위만 완료로 기록한다.

이번 완료 범위는 **활동 그룹의 기술 집계**다. 기존 전체 구현 범위의 신뢰구간·시기 분리·콘텐츠/클릭 민감도·운영 연결·UI·배포는 이 집계 제출과 구분한다. 이번 단계에 새로운 분석 방법이나 사람 실측을 추가하지 않는다.
