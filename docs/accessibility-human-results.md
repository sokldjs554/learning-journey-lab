## 오류 안내·복구: 사람과 자동 검사 구분

| 대상 | 사람이 전달한 근거 | 기술 검사 |
|---|---|---|
| 메인 | 실제 오류 화면 이미지, ‘근거 파일 불러오기 실패’ 자동 읽기, 키보드 재시도 성공, 복구 직후 ‘학습 지표 검토’ 읽기 | 공개 URL의 실패·재실패·복구 초점 회귀 통과 |
| EdNet | ‘보조 근거 확인 실패’, 키보드 재시도 질문에 정상 접속 응답, 복구 직후 ‘보조 데이터 검증’ 읽기 | 공개 URL의 실패·재실패·복구 초점 회귀 통과 |
| 실습 | 정상 준비 화면 이미지와, 문구를 읽은 뒤 자동 복구됐다는 최종 정정 보고 | 로컬 브라우저 회귀에서 오류/재시도와 준비 제목 초점 확인. 사람의 자동 복구 보고를 키보드 재시도·초점 이동이나 소프트웨어 자동 재시도 기능의 증거로 사용하지 않음 |
| 검증 계획 | 이 문서의 사람 확인 범위는 정상 상태의 선택·표 읽기 | 실패·재실패·결과 영역 초점은 공개 URL 자동 회귀 근거를 사용 |

실습의 오류 문구로 전달된 ‘근거 파일 불러오기 실패’는 메인 화면 문구와 같아 실습 고유 오류 발화의 확인 근거로 사용하지 않았다. 로컬 도구는 첫 요청만 실패시키고 뒤 요청에는 정상 파일을 제공한다. 따라서 정상 화면 이미지나 재접속만으로 사용자가 재시도 버튼을 키보드로 실행했다고 판단할 수 없다. 실제 음성을 녹음·직접 관찰한 자료는 없으며, 자동 검사는 사람의 발화 증거를 대신하지 않는다.

## 안내·수정 이력과 검토의 한계

- Codex가 조작 순서·기대 수치·용어를 설명한 안내형 QA다. 별도 처음 보는 참여자의 사용성 평가와 합치지 않는다.
- 최초 숫자 전사와 설명 문장을 실제 결과값으로 혼동한 응답은 최종 정정과 구분했다. 1,337명은1,377명으로, 실습의 ‘정상판정’ 표현은 실제 판정 열의 ‘무효’로 정정받았다. 화면 읽기 소프트웨어의 버그를 발견·수정했다고 주장하지 않는다.
- Codex가 ‘품질 상태’라고 안내한 실제 라벨은 ‘판단 상태’였다. 표본 선택 상자는 접힌 상세 안에 있었고, Tab만으로는 일반 출력 문구를 건너뛸 수 있어 안내를 바로잡았다. 이 설명 문제를 사용자 탓이나 제품 결함으로 재분류하지 않는다.
- 생성 로그5단계와 전체 확인 묶음 수를 명확히 구분하지 않아 범위 안내가 혼란스러웠다. 로컬 서버 시작 안내를 페이지 오류로 오인하거나 다른 경로를 연 경우도 있었다. 서버 시작·Safari 연결 실패·정상 화면 자체를 앱의 오류 재시도 성공으로 세지 않았다.
- 이전 환경 보고는 Safari16.6.1·Samsung Internet30.0.5.27이다. 이번 후속 실행의 정확한 OS/VoiceOver/브라우저 버전을 새로 수집하지 않았으므로 과거 버전에 대한 전체 호환성 보장으로 쓰지 않는다. 개인 브라우저 북마크 등이 보이는 원본 캡처는 공개하지 않는다.

사용자의 추가 재확인 종료 요청에 따라 받은 근거로 정리했다. 선택한 경로의 직접 조작·자기 보고, 개발자의 코드/브라우저 검사, 모든 기기·모든 상태의 적합성 인증은 서로 다르다. 이 문서는 첫 두 범위의 근거만 제공한다.

포트폴리오에 사용할 수 있는 표현: **“Safari·VoiceOver와 Android에서 안내된 주요 읽기·탐색·확대·터치 과제를 직접 확인하고 결과를 전달했다. 수치와 문구를 재대조하고, 사람의 보고와 개발자 자동 검사의 증거 범위를 구분해 기록했다.”**
