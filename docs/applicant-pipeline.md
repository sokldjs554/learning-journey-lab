## 구현과 확인

원본 검증 → DB 적재 → 품질20규칙 → 기본/strict 분석표 → 집계 → 통계를 기존 모듈7회 호출로 연결한다. 현재 Python과 인자 리스트를 사용하며 다른 작업 폴더·공백/따옴표가 있는 경로에서도 동작한다. 매번 새 실행 폴더와 단계별 stdout/stderr, 원자적으로 교체하는 run_record.json을 만든다.

품질 PASS/REVIEW는 진행하고 BLOCK은 후속 실행을 멈춘다. manifest 형식 오류의 자식 종료2는 품질 BLOCK과 구분해 파이프라인 오류1로 남긴다. 필수 산출물·입력 해시·집계/통계 분자/분모·비율 단위·전체 활동 그룹 합계를 성공 전에 대조한다. 원본/코드 경로 충돌, 의존 파일 누락, 잘못된 JSON, 출력 누락, 중간 실패를 검사했다. 제어된 KeyboardInterrupt와 디스크 저장 실패도 성공으로 기록되지 않았다.

## 실제 OULAD 2회 실행

Codex가 기존 원본7CSV를 사용해 별도의 새 DB에서 전체 흐름을 두 번 실행했다.

| 실행 | 종료 | 품질 | 적격 수강 건 | 첫 주 활동 | 다음 주 재방문 | 경과초 |
|---|---:|---|---:|---:|---:|---:|
| 1 | 0 | REVIEW | 29,671 | 23,522 | 20,303 | 47.018274 |
| 2 | 0 | REVIEW | 29,671 | 23,522 | 20,303 | 43.693040 |

두 실행 모두 통계7묶음이 기존 참고값과 정확히 일치했다. 품질·집계·통계의 분석 값이 반복 일치했고, 산출물 해시를 실제 파일과 대조했다. 원본·manifest·제출 코드와 첫 실행의 모든 결과·로그는 내용 및 수정 시각이 보존됐다. 새 DuckDB 바이너리 해시는 달랐으므로 실행 ID·시간·입력 DB 해시를 포함한 JSON 전체가 같다고 주장하지 않는다. 위 시간은 **Codex 실행 환경의 경과 시간**이며 사람 노동 시간이나 절감 효과가 아니다.

## 테스트 수정 이력

첫 검사에서35개 통과·2개 실패가 발생했다. Codex가 만든 CSV의 초기 행은 CRLF, 추가 행은 LF여서 DuckDB가 CSV 형식을 읽지 못했다. 실패 로그로 적재 단계 중단을 확인하고 추가 행도 csv.writer로 작성하도록 테스트만 수정했다. 이후37개를 통과했다. 제출 코드의 결함이나 지원자가 수정한 작업으로 기록하지 않는다.

지원자는 이 파일을 제출했다. Codex는 원형 보존, 코드 검토, 생성 자료 테스트, 실제 자료2회 실행, 결과 대조와 문서화를 수행했다. 이번 첨부에는 지원자의 로컬 실행 출력이 없었으며 이를 대신 만들어 기록하지 않는다. 통합 실행 근거는 합의한 마지막 통합·배포 단계에서 구분해 수집한다.

다음은 이미 합의한 운영 연결의 **이슈 이력·독립 계산 대조·단계별/일괄 비교 도구 연결**이다. 앞서 완료한 SQL·통계·사람 실측을 반복하는 과제가 아니다. 운영 나머지와 EdNet·생성 시나리오·UI·통합 검증/배포는 [고정 계획](applicant-completion-plan.md)을 따른다. 이번 제출을 전체 프로젝트 구현 완료로 확대하지 않는다.
