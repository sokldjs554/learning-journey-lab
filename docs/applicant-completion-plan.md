# 전체 직접 구현: 남은 범위와 완료 기준

2026-11-06 KST. 사용자가 통계·운영 연결·EdNet·생성 시나리오·UI·배포를 직접 구현하고 검증하는 범위로 진행하기로 했다. 전날의 지원 자료 정리와 별개의 후속 선택이다. 채용 지원에 모든 코드 재작성이 필수라는 뜻이 아니다.

**아래 여섯 범위를 기존 제출 코드에 연결하고 테스트·공개 배포 동작까지 확인하면 합의한 전체 직접 구현 범위를 완료한다. 이후 새 기능·추가 사람 실측·새 참여자 모집·모든 기기의 접근성 인증을 완료 조건으로 붙이지 않는다.** 검증 중 실제 오류가 발견되면 해당 오류의 수정과 관련 재검증을 포함한다.

현재 진행: **통계·민감도 제출·기능 검토 완료**, 남은 작업은 운영 연결·EdNet·생성 시나리오·UI·통합 검증/배포다. [원본·39개 검사·실제 자료 대조](applicant-statistics.md). 제출 명령만으로 지원자 로컬 실행을 완료했다고 기록하지 않는다.

## 그대로 유지하는 완료 항목

원본 검증, DuckDB 적재, 품질20규칙·판정·저장, 수강 건별 분석표, 전체·개설기별 활동 집계의 제출·기능 검토는 완료했다. 앞선 활동 기준 SQL·손계산·판단, v1/v2 실측, 안내받은 실제 기기·VoiceOver QA도 완료한 범위를 유지한다. 기존 제출 코드와 테스트를 재사용한다.

## 남은 여섯 범위

| 순서 | 범위 | 이번 목표에서 완료로 판단할 동작 |
|---|---|---|
| 1 | 통계·민감도 — 제출·기능 검토 완료 | 전체·개설기의 활동일/콘텐츠 비교와 최초 활동일별 활동일 비교, 학습자 단위 신뢰구간, 2013/2014 분리, 클릭10/20/50 정책·strict 비교·후속 활동 전환. [이번 제출 계약](applicant-statistics-spec.md) |
| 2 | 운영 연결 | 기존 제출 모듈과 통계를 한 번에 실행, 실패·BLOCK 시 후속 중단, 결과·실행 기록·이슈 이력 저장, 같은 입력 재실행 일관성과 별도 계산 대조. 기존 단계별/일괄 운영 비교의 입력 수정·중단·시간 기록 동작도 연결하며 개발용 예시로 검사. 새 사람 실측은 하지 않음 |
| 3 | EdNet | 기존 고정 표본·출처·라이선스·해시 검증, 이벤트 정의별 활동/유료 기록 범위, 품질·관측 한계, 독립 대조와 결과 파일 생성. 표본 확대·새 데이터 수집을 추가 조건으로 삼지 않음 |
| 4 | 생성 시나리오 | 기존 정상/장애/정리/지연/재수집5단계, 생성 구독 원장 연결, 실험 입력·표본·모집 시나리오 검증. 생성 자료 표시 유지. 실제 서비스 실험·성과로 바꾸지 않음 |
| 5 | UI | 본인 구현 결과와 연결된 지표 검토·재방문·실행 기록·검증 계획·생성 로그·EdNet·운영 실습. 출처·분자/분모·필터·PC/모바일·키보드·빈/오류/재시도 확인. 기존 화면 구조와 스타일 재사용 가능 |
| 6 | 통합 테스트·CI·배포 | 앞선 구현을 연결한 실행과 독립 기준값 대조, 오류·경계·반복·화면 수치 검증, 해당 코드의 원격 CI와 공개 데모 동작. 배포된 코드/결과 버전과 범위 기록 |

이는 제출 파일6개나 작업6회라는 뜻이 아니다. 각 범위의 기존 기능을 한 묶음으로 적은 것이다. 앞선 생산 구현의 파일 이름·내부 구조를 그대로 복제할 필요는 없다. 새 로그인·실시간 서버·추천·LLM 기능은 추가하지 않는다.

## 역할과 증거

- 지원자: 직접 구현한 코드 제출, 본인 환경에서의 연결 실행·테스트·배포 작업, 주요 선택·수정 이유와 참고한 코드/도움 범위 기록. 기존에 완료한 설명이나 실측을 반복 제출하지 않는다. 통합 실행 단계에서 실제 새 구현 실행 근거를 모은다.
- Codex: 입력·출력·검증 계약 정리, 환경 안내, 제출본 원형 보존·코드 리뷰·별도 테스트·실제 자료 대조·문서화. 완성 코드를 제공한 부분이 생기면 도움받은 구현으로 기록한다.
- 코드 참고와 재사용은 허용한다. 변경한 부분과 직접 작성한 부분을 구분한다. 모든 파일을 새로 타이핑하거나 무도움 작성 사실을 입증하는 시험이 아니다.
- 완료는 위 범위의 본인 구현·통합 사례를 확보했다는 뜻이다. 회사 실제 성과나 모든 상황의 개발 숙련도를 인증하지 않는다.

새 UI에 대한 동작 검증은 해당 변경의 테스트다. 기존 사람 실측이나 실제 기기 QA 완료를 취소해 다시 진행시키는 근거로 사용하지 않는다. 문제없이 재사용하는 부분에는 테스트를 위한 테스트나 새로운 사용자 모집을 요구하지 않는다.

## 첫 묶음 완료와 다음 순서

`learning_stats.py`, `run_statistics.py`를 수신했고 원본 수정 없이 검토를 통과했다. 기존 보고서의7개 결과 묶음이 실제 자료에서 두 번 모두 일치했다. 다음은 위2번 운영 연결이다. 이미 검증한 원본·품질·분석표·집계·통계 모듈을 재사용하며 통계 파일을 다시 작성하는 단계가 아니다. 요구사항이나 기존 참고값을 실제 실행 근거로 대신하지 않는다.
