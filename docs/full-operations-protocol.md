# OULAD 전체 운영 비교 — 사람 측정은 아직 시작하지 않음

**A: 단계별 실행 + 직접 결과 기록 / B: 같은 계산의 일괄 실행 + 자동 채움 결과 확인.** 두 방식 모두 같은 84개 항목과 통계 요약을 확인합니다. 코드를 처음부터 작성하거나 통계를 손으로 계산하는 비교가 아닙니다. AI 호출도 없습니다.

기존 3개 규칙 UI 실습 결과와 100초 자기보고 재실행은 별도 과제입니다. 이 비교의 수동 기준으로 바꾸어 쓰지 않습니다.

## Mac에서 시작하기

업데이트된 저장소 ZIP을 받아 **기존 폴더 옆의 새 폴더**에 풉니다. 기존 CSV·가상환경·보고서는 그대로 둡니다. 아래 두 경로만 실제 폴더로 바꾸세요. 이미 활성화된 가상환경을 계속 쓴다면 첫 줄은 생략합니다.

```bash
source "/기존폴더/.venv/bin/activate"
cd "/새코드폴더"
python scripts/full_operations.py init --raw-dir "/기존폴더/data/raw" --provenance human_self_reported
python scripts/full_operations.py run
```

`init`은 시간을 재지 않는 사전 전체 검증입니다. 처음 `run`은 **연습 A**, 다음은 **연습 B**입니다. 같은 `run` 명령을 계속 입력하면 본 측정 **A → B → B → A → A → B**가 순서대로 나옵니다. 총 8회이며 조건을 직접 고르거나 건너뛰지 않습니다. 개발자 자동 시험은 반드시 `--provenance developer_synthetic`으로 별도 폴더에 기록합니다.

- 준비되면 `start`를 입력합니다. 이때부터 측정합니다.
- A에서는 각 단계에 `run`을 입력하고 표시된 값을 기록합니다. **복사·붙여넣기 허용**입니다. 숫자에는 쉼표를 넣지 않습니다.
- B에서는 12단계를 일괄 실행한 뒤 같은 항목이 채워진 확인 화면을 차례로 봅니다.
- 두 방식 모두 화면의 항목과 비교 요약을 확인한 뒤 `reviewed`를 입력합니다. 전체 JSON의 모든 값을 읽는 과제는 아닙니다.

한 회차에는 12개 확인 화면과 총 84개 확인 항목이 있습니다. A는 `start` 1회, `run` 12회, 직접 값 기록 84회, `reviewed` 12회가 필요합니다. B는 `start` 1회와 `reviewed` 12회가 필요하며, 확인하는 항목은 같습니다. 수동 입력과 클릭 수 자체를 주의 집중 시간이나 절감 효과로 해석하지 않습니다.

```bash
python scripts/full_operations.py status
python scripts/full_operations.py audit > work/full-operations/audit-summary.json
```

`status`는 진행 상태만 표시합니다. `audit`은 원본 해시, 코드·환경, 보존된 결과, 입력 기록, 이벤트와 시간의 일관성을 다시 검사합니다. 오류 없이 나온 `audit-summary.json`은 개인 경로와 학습자 ID가 없는 검토용 요약입니다. 결과 공유 전에는 이 검사를 실행하고 **무효·중단 시도까지 함께** 검토합니다. `work/enrollment_mart.csv`에는 학습자 키가 있으므로 요약 대신 전체 작업 폴더를 공개하지 않습니다.

기본 저장 위치는 `work/full-operations/`입니다. 다른 위치를 쓰려면 모든 명령에 `--study /새로운/폴더`를 동일하게 추가합니다. 코드 또는 Python·패키지를 바꿨다면 새 study 폴더에서 다시 시작합니다. 중간에 환경을 바꾼 회차를 섞지 않습니다.

## 실제 계산 범위와 사람이 확인하는 범위

| 단계 | A/B가 모두 수행하는 계산 | 공통 확인·기록 항목 |
|---|---|---|
| 원본 불러오기 | CSV 7개 해시 검증과 테이블 적재 | 파일 수, manifest에 고정된 원본 ZIP 식별자(CSV 7개는 이번 단계에서 재검증, ZIP 자체는 재해시하지 않음) |
| 품질 | 기존 20개 규칙 전체 | 20개 규칙별 건수, 집계 차단 여부 요약 |
| 분석표 | 기본·탈퇴 이후 제외 분석표, 기본 SQL 뷰 복구 | 대상 수, 엄격 기준 첫 주·다음 주 수 |
| 전체 통계 | 기존 요약과 학습자 단위 bootstrap | 대상·첫 주·다음 주 수, 두 비교의 유효 재표집 수, 차이·95% 구간 요약 |
| 22개 개설기 | 모든 개설기의 기존 통계·bootstrap | 각 대상 수와 반복 활동·콘텐츠 비교의 차이·95% 구간 |
| 시기 분리 | 2013 탐색, 기존 등록자를 제외한 2014 신규 학습자 검증 | 각 대상·첫 주·다음 주 수와 비교 요약 |
| 민감도 | 첫 활동일별 비교, 클릭 10/20/50, 활동 전환 | 집단 수, 클릭 기준별 변경 수, 전환 수, 첫 활동일별 비교 요약 |
| 가상 장애 | 기존 생성 장애·정리·지연·복구 실습 | 가상 자료 표시, 장애 6개 건수, 복구 단계 요약 |
| 보고서·이력 | 보고서·분석표 저장, 고정된 이전 이력에서 이슈 갱신, 기존 실험 표본 수 계산 | 보고서 SHA, 분석표 행 수, 이슈·이력 수 |
| 독립 대조 | 원본 CSV의 독립 pandas 계산 | 대조 행·항목·불일치 수 |
| 빌드 | 기존 정적 자료 빌드 | 보고서 SHA, 빌드 상태 |
| 검증 | 기존 보고서·웹 자료·문서 일관성 검사 | 보고서 SHA, PASS |

모든 계산은 기존 방식 그대로 수행하고, 사람의 확인은 표에 고정된 항목과 간결한 요약으로 제한합니다. 전체 결과는 각 시도의 `stages/`에 별도 저장됩니다. 기존 EdNet 결과·과거 벤치마크·문서·이슈 이력은 빌드에 필요한 고정 입력으로 복사합니다. 별도 EdNet 분석이나 과거 벤치마크를 이번에 다시 측정했다고 표현하지 않습니다.

## 시간·오류 처리와 해석

- 설치·다운로드·폴더 준비·사전 해시 확인·사전 검증·연습은 본 측정에서 제외합니다. 실제 원본 해시·적재 단계는 A/B 모두 측정 안에서 다시 수행합니다.
- `elapsed_seconds`: 시작 후 전체 경과 시간. `pause_seconds`: 명시적으로 선언한 휴식. `unpaused_seconds`: 휴식을 뺀 시간. `machine_seconds`: 단계 실행 대기 시간 합계. `non_machine_unpaused_seconds`: 그 밖의 입력·확인·대기·기록 처리 시간입니다. **어느 값도 실제 주의 집중 시간을 측정하지 않습니다.** 원래 분석의 `latest_run.json`에는 A의 중간 입력 시간이 섞일 수 있어 비교에 쓰지 않습니다.
- 입력 대기 중 `:pause`로 휴식을 시작하고 Enter로 돌아옵니다. 계산 중 휴식을 나중에 소급 신고하지 않습니다. `:abort`, Ctrl-C, 입력 종료는 중단 시도로 남습니다. 강제 종료는 다음 실행에서 중단으로 표시하며 알 수 없는 종료 시각·시간을 만들지 않습니다.
- 잘못된 값, NaN, 확인 누락, 결과 해시 불일치, 계산 실패는 무효입니다. 원래 입력과 정오 여부를 보존하며 해당 시도에서 수정하지 않습니다. 다음 `run`은 같은 예정 회차를 새 폴더에서 명시적으로 재시도합니다.
- **완료된 회차만 골라 평균·중앙값·절감률을 내지 않습니다.** 먼저 각 조건의 완료·무효·중단 수, 모든 시도의 관측 시간과 모르는 시간을 함께 보고합니다. 본 측정 6회가 끝나도 한 사람의 고정 자료 반복 과제이며 학습·순서 효과가 있습니다. 일반적인 생산성 향상이나 절약한 주의 시간을 주장하지 않습니다. 도구는 효과 크기나 절감률을 자동 산출하지 않습니다.

`protocol.json`은 코드 SHA, Python·플랫폼·패키지 버전, 원본·고정 입력·단계별 결과·최종 결과 해시를 저장합니다. 시도마다 별도 폴더, `record.json`, 덧붙이는 `events.jsonl`을 만듭니다. 입력 자료 유형도 모든 기록에 표시합니다. 동시 실행과 같은 단계의 재진행은 차단하며, 완료된 8회 뒤에는 새 회차를 만들지 않습니다. 로컬 로그는 검토 근거이지 변경 불가능한 증명이나 인간의 주의 집중 증거는 아닙니다.

원본 CSV는 읽기만 하고, 생성 자료·데이터베이스·보고서·분석표·빌드는 시도 폴더에만 씁니다. 기존 보고서와 이력은 덮어쓰지 않습니다. 개발 검증에서 시도당 약 65 MB였으며 환경에 따라 달라집니다.
