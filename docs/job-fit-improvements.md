## 후속 공고 대조의 네 항목: 완료와 한계 구분

아래는 위 구현 보완 네 항목과 별개로, 후속 공고 대조에서 언급한 설명·의사결정·측정·현업 적용의 정리다. **지원자의 기준 비교 실습은 완료했으며 추가 필수 실습은 없다.** 확인되지 않은 회사 성과는 프로젝트의 적용 한계이지, 지원자에게 회사 접근 권한이나 재측정을 요구하는 미완료 과제가 아니다.

| 후속 검토 항목 | 확인된 근거와 현재 상태 | 표현의 경계 |
|---|---|---|
| 직접 설명할 수 있는 기술 | 세 집단 SQL 제출·실행 결과, 분자/분모 계산, 가상 8행의 손계산 대조, 관찰과 인과 구분을 확인. 실습 완료 | 다른 통계 기법까지 개인 숙련이 입증됐다고 확대하지 않는다. 그 기법을 모두 다시 설명하는 것을 완료 조건으로 추가하지 않는다 |
| 분석을 결정에 쓰는 맥락 | 활동 기준 변경의 타당성 검토: 2일 이상→3일 이상에서 4,803건 제외, 관찰 비율 +3.1%p. 비율만으로 기준을 높이지 않는 이유를 제출 | 최적 기준이나 안내 대상 정책을 확정한 분석은 아니다. Codex가 최초 과제에서 정책의 용도·비용을 고정하지 않았으므로 이를 지원자의 설명 누락으로 평가하지 않는다 |
| 자동화 효과 측정 | 지원자가 직접 비교 측정. 실패 시 전체 재시작 부담을 발견해 Codex가 v2를 구현·검증 | 과거 v1·개발 자동 검사·v2 사람 실측을 구분. 후속 요청으로 v2 본 측정 6회 완료; 1인 반복 관측으로 회사 생산성이나 v1 대비 효과를 확정하지 않음 |
| 실제 회사 업무·성과 연결 | 공개 데이터 분석, 별도 참여자의 데모 검토, 조건부 개선안·실험 설계를 확보 | CLASS101 내부 적용·실제 갱신/재방문 개선은 수행하지 않았다. 데모 피드백을 회사 정책 채택이나 실험 효과로 표현하지 않는다 |

2026-11-05 추가 요청의 v2 사람 실측은 종료했다. UI·배포 포함 독립 구현은 별도로 선택된 범위이며 기존 SQL 실습 완료를 취소하지 않는다. Codex의 후속 작업은 기존 근거를 문서에 연결하고 역할·수치·한계를 일치시키는 것이다. 지원자에게 이미 완료한 검증을 반복 요구하지 않는다. [직접 수행과 구현 역할](participation.md), [설명에 사용할 사실](evidence-map.md), [완료한 실습의 설명 예시](interview-guide.md#완료한-기준-비교-실습-설명)를 따른다.

## 설명에서 앞에 둘 판단

클릭 임계값의 민감도 때문에 첫 학습 성공 기준을 보류한 판단, 개설기별 반대 근거 때문에 콘텐츠 확대를 보류한 판단, 활동일의 관찰 관계와 실제 개선 효과를 구분한 판단을 먼저 설명한다. 배포·접근성·브라우저 테스트는 결과를 신뢰하고 읽을 수 있도록 한 보조 근거다.

추가 기법의 개수나 생성 예제의 갱신율을 성과로 내세우지 않는다. 본인이 직접 설명·수정한 부분은 [참여 기록](participation.md)을 기준으로 쓰며, 지금 추가한 코드의 구현자는 Codex다.

## 직접 재현

기존 가상환경·의존성이 있는 저장소에서 아래 두 명령은 새 원본 다운로드 없이 실행된다.

```bash
python scripts/check_subscription.py
python -m pytest -q tests/test_subscription_bridge.py tests/test_full_operations.py
```

전체 OULAD의 v2 통합 검증은 [별도 명령](full-operations-v2.md#개발-검증)을 따른다. 개발자 자동 입력과 사람의 실측은 다르며, 사람이 새 측정을 하지 않아도 구현 검증은 실행 가능하다. 기존 공개 데모의 분석값은 변경하지 않는다.
