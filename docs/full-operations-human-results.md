# 전체 OULAD 운영 비교 — 지원자 실행 결과

2026-11-01 KST 수신 기준. 지원자 1명이 연습 A/B 후 본 측정 ABBAAB의 6개 예정 회차를 완료했다. **완료 6회 외 무효 5회를 보존**했다. 사용자가 전달한 최종 로컬 감사 출력은 `audit: PASS`, `completed_measured: 6`, `invalid_attempts: 5`, `aborted_attempts: 0`, `next: null`이다. [요약 원문과 집계](../reports/full-operations-human-results.json).

## 비교한 업무와 확인 범위

A는 같은 분석의 단계별 실행·직접 값 기록, B는 일괄 실행·자동 채움 결과 확인이다. 계산 범위는 OULAD 12단계이며 공통 확인 대상은 84개 항목과 통계 요약이다. 손계산·처음부터 SQL 작성·독립 분석 설계의 시간 비교가 아니다. [고정 절차](full-operations-protocol.md).

Codex는 전달된 요약의 회차 순서, 상태별 개수, 시간 합계·차감 관계와 조건별 합계를 검사했다. 합계는 `math.fsum`과 십진수 `Decimal`로 독립 대조했다. 전체 `protocol.json`, 측정 회차별 `events.jsonl`·단계 결과 파일은 받지 않아 맥북에서 수행한 원본 감사 전체를 Codex가 재실행한 것은 아니다. 따라서 **사용자가 실행해 전달한 감사 결과**와 **요약에 대한 Codex의 산술 검사**를 구분한다. 연습 A의 `record.json`은 별도로 받아 12단계·84개 입력·9개 선언된 산출물 해시를 검토했다.

## 모든 본 측정 시도를 포함한 결과

| 방식 | 완료 | 무효 | 중단 | 관측된 모든 시도 경과 합계 | 계산 대기 합계 | 계산 대기 외 구간 합계 |
|---|---:|---:|---:|---:|---:|---:|
| A 단계별 실행·직접 기록 | 3 | 5 | 0 | 5,019.92초 | 812.94초 | 4,206.98초 |
| B 일괄 실행·자동 채움 | 3 | 0 | 0 | 616.49초 | 340.13초 | 276.36초 |

두 방식 모두 **기록된** 일시정지는 0초다. 이것만으로 실제 휴식·중단이 없었다거나 계산 대기 외 시간이 모두 집중 작업이었다고 단정하지 않는다. 연습·설치·사전 검증과 시도 사이 간격은 이 합계에 포함되지 않는다. A의 계산 대기에는 무효 시도에서 다시 실행한 계산도 포함된다. 완료한 회차만 골라 절감률·중앙값을 발표하지 않는다.

| 예정 회차 | 방식 | 실제 시도 번호 | 무효 시도 수 | 해당 회차의 모든 시도 경과 합계 |

표는 반올림했지만 원본 정밀도는 JSON에 보존했다. 마지막 B의 계산 대기 외 구간은 27.71초다. 확인 문구가 입력됐다는 사실만으로 84개 항목과 통계 요약을 같은 깊이로 읽었다고 입증할 수 없다. 지원자는 후속 질문에 B에서도 자동 채움 값과 비교 요약을 모두 읽고 확인했다고 답했다. 이는 자기 보고이며 동일한 이해 수준의 독립 검증은 아니다.

## 실패에서 확인한 도구의 한계

사용자가 무효 기록의 `reason`을 읽어 전달했다. 시도 6·9·11은 표시값과 입력값 불일치, 8·10은 실행 문구 `run`이 입력되지 않았다는 사유다. 후자 둘은 `invalid_inputs: 0`이어서 값 입력 오류로 합치지 않았다. 입력 원문·어느 필드에서 발생했는지는 아직 확인하지 못했다.

A에는 값 전사와 단계별 실행 명령이 추가된다. 현재 도구는 실행 문구 오류에도 해당 시도를 무효로 끝내고 회차 전체를 재시작한다. 따라서 결과에는 자동 채움의 차이뿐 아니라 **도구의 입력 방식·엄격한 실패 처리 비용**이 들어 있다. 이를 일반적인 수작업 분석의 비효율, 업무 정확도 개선, 회사의 비용 절감으로 확대할 수 없다. 원래 회차나 측정 규칙을 사후 수정하지 않았다.

실측 정리 당시 후속 개선 후보는 잘못된 실행 문구를 해당 입력에서 다시 묻는 방식이었다. 이후 2026-11-02 [v2 입력 수정 방식](full-operations-v2.md)을 구현했다. 기존 결과에 수정된 규칙을 소급 적용하지 않는다. 새 사람 측정은 수행하지 않았으며, 비교 검토의 깊이는 별도 이해 확인 과제로 평가하고 새 참여자와 순서 분산을 통해 반복 학습 영향을 확인해야 한다.

## 직접 수행과 도움

- 지원자: 기존 원본 폴더 연결, 사전 검증 실행·출력 전달, 연습 A/B, 본 측정 완료 6회와 무효 5회, 로컬 감사와 무효 사유 출력 전달.
- Codex: 도구·분석 구현, 개발자 동등성 검증, 폴더/가상환경 안내, 비어 있던 원본 경로 변수 진단, 연습 A의 값 입력 도움, 회차 전 안내, 전달 결과의 검토·산술 대조·문서화.
- 연습과 본 측정 사이의 도움을 구분한다. 최종 질문에 지원자는 본 측정 1~6회 중 기록하지 않은 휴식·중단·진행 중 외부 도움이 없었다고 답했다. 이 자기 보고와 Codex의 준비·연습 도움·회차 전 안내를 함께 기록한다.
- 측정 시작 전 오류에는 Python 3.11 경로가 보였고 이전 원본 재현은 Python 3.14로 보고됐다. 이번 측정의 정확한 런타임은 프로토콜을 아직 받지 않아 미확인이다. 안내한 코드 기준은 `95e8c205deaba7868d56bfda6df2c6035ab8abe1`이며 전체 코드·환경 지문을 독립 확인한 것은 아니다.

## 사용할 수 있는 표현과 남은 검증

“같은 OULAD 계산의 단계별 실행·직접 기록과 일괄 실행·자동 채움을 직접 비교했다. 예정 회차 6개를 완료했고 무효 시도 5개도 보존했다. 재시도 원인을 구분하면서 도구의 입력 방식이 측정 결과에 미치는 한계를 확인했다.”

‘전체 분석을 손으로 수행’, ‘오류를 없앰’, ‘회사 생산성을 일정 비율 개선’, ‘모든 내용을 독립적으로 설계·검증’으로 표현하지 않는다. 한 사람·같은 자료·고정 순서로 학습 효과를 분리할 수 없고, 같은 검토 대상이 같은 이해 수준을 보장하지 않는다. 기존 3규칙 UI 실측·100초 재실행은 별도 과제다.

미확인: 전체 실행 로그·프로토콜의 독립 감사, 정확한 측정 런타임, 두 방식의 이해 수준에 대한 독립 평가. 기록 밖 중단·도움 없음과 B 전체 읽기·확인은 지원자 자기 보고로 확인했다. [실제 기기·VoiceOver 확인](accessibility-human-results.md)은 별도 근거로 정리했다. 회사 내부 실험은 이 시간 측정과 접근성 확인으로 수행한 것으로 바뀌지 않는다.
