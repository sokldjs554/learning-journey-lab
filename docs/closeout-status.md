## 직접 수행 결과가 필요한 항목

추가 진행 요청에 따라 [실제 진행 절차](remaining-validation-execution.md)를 준비했다. 사용자는 맥북·안드로이드와 Python·SQL 설치·실행 경험을 보고했다. 직접 CI 화면 확인, 실제 프로그램 버전·동작은 대기다. 회사 권한은 획득 방법을 안내했으며 확보된 것으로 기록하지 않는다. 절차 준비를 실제 수행 완료로 집계하지 않는다.

| 항목 | 확인된 현재 상태 | 다음 확인과 완료 기준 |
|---|---|---|
| 처음 보는 참여자 사용성 | 1명의 네 과제 응답·도움 없음 보고와 익명 요약 공개 동의 확인. 검증 계획 문구 수정 | [결과와 한계](usability-results.md). 수정 후 4번 재검토 응답 수신. 더 읽기 편하다는 평가·추가 질문 뒤 목적 설명 확인. 실제 실험 미실행 구분은 미확인. 문구 수정의 인과 효과는 주장하지 않음 |
| 지원자의 새 테스트 CI 읽기·코드 설명 | 파일 추가·커밋은 확인. 새 CI 성공은 Codex가 확인 | [실습 CI](https://github.com/sokldjs554/learning-journey-lab/actions/runs/41011751113) → verify → pytest 단계의 결과를 직접 확인하고, `tests/test_user_repeat.py`에서 왜 기대값이 2인지 본인 말로 설명. 실제 응답 후에만 참여 기록에 추가 |
| 전체 SQL·통계 분석의 사람 수작업 기준선 | 미측정. 3개 규칙 기록 실측은 완료 | [작업 범위](operations.md)를 먼저 맞추고 실제 환경·숙련도를 확인. 설치·학습과 반복 업무를 분리. 사람의 작업 기록·동일 산출물 확인 없이 Codex 실행 시간을 대신 사용하지 않음 |
| 실제 Safari·물리 휴대폰·스크린 리더 | 미실시. CI WebKit과 화면 폭 검사는 완료 | 실제 장치/브라우저/보조 기술명·버전과 수행 경로를 받은 뒤 해당 범위만 기록. 화면 설명 읽기, 키보드 이동, 오류 안내, 분모·출처 접근 등을 직접 확인. 자동 axe 결과를 사람이 읽을 수 있다는 증거로 바꾸지 않음 |
| CLASS101 실제 사용자 A/B·갱신·매출 효과 | 미실시. 공개 자료 분석·실험 설계·합성 입력 검사는 완료 | 서비스 운영 권한, 배정·동의·로그 품질·관측 기간과 실제 결과 필요. 외부 데모 사용성 참여자를 CLASS101 실험 참여자로 세지 않음 |

전체 사람 기준선을 시작할 때는 사용 중인 운영체제와 실행 가능한 도구부터 확인한다. 예를 들어 macOS/Linux 터미널은 `python3 --version`, Windows PowerShell은 `py --version`으로 확인할 수 있지만 설치되어 있다고 가정하지 않는다. 명령이 없으면 오류를 그대로 남기고 설치·학습은 측정에서 제외한다. 환경 없이 가능한 기존 GitHub Actions 실습은 자동 재현 확인이며 사람의 수작업 분석 시간 측정을 대신하지 않는다.

이 문서는 남은 일을 완료로 바꾸기 위한 양식이 아니다. 실제 과제 결과·장치 검토·사람 작업 기록을 받은 뒤 근거와 상태를 갱신한다.
