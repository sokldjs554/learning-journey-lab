## 수정과 출처

## 확인한 수정 효과

기존에는 처음 처리하는 실행의 quality.json을 바꿔도 실행 기록의 저장 해시와 비교하지 않았다. 실제 결과의 **복사본**에서 등록일 결측45→0으로 바꾸면 REVIEW 판정이 유지돼 잘못 resolved 처리됐다. 이는 실제 원본 수정이나 실제 사용자 사고가 아닌 Codex의 통제된 재현이다.

수정본은 실행 기록에 artifacts가 있을 때 품질 파일 메타데이터와 해시를 검사한다. 불일치하면 이력을 읽어 적용·저장하기 전에 오류1로 종료한다. 같은 복사본 재검사에서 등록일 결측은45건/open으로 남았고, 기존 이력 파일 내용과 수정 시각도 유지됐다.

| 검증 | 수정 전 | 수정 후 |
|---|---|---|
| 기록된 해시와 다른 품질 파일 | 수용·종료0 | 거부·종료1 |
| 기존 등록일 결측 이슈 | 잘못 resolved | 45건/open 유지 |
| 기존 이력 내용·수정 시각 | 변경 | 보존 |

품질 BLOCK이나 품질 성공 후 후속 단계 실패는 기존 파이프라인 계약상 최종 artifacts가 null일 수 있다. 이 경우 기존 품질 단계 상태·종료 코드·20규칙·gate 검증을 유지하며, 실행 기록과 파일 해시를 대조했다는 보장은 붙이지 않는다. 잘못된 artifacts 구조, 품질 메타데이터 누락/null, 해시 누락도 오류로 처리하고 기존 이력을 보존한다.

## 회귀와 실제 결과

39개 검사는 발생→해결→재발, 건수 변경, clear 상태, 같은 실행 재처리, 동일 값의 새 실행, 품질 BLOCK 및 나중 단계 오류, 잘못된 입력/기존 이력, 경로 충돌, 원자적 저장 실패, 해시 불일치·메타데이터 오류를 확인했다. 이전 실패 검사도 일반 검사로 통과해 strict xfail 마커를 제거했다.
