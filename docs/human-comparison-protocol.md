# 실제 사람이 수행할 3개 규칙 기록 비교

현재 상태: **지원자 1명의 연습 A/B·ABBAAB 6회 및 원본 JSON 검증 완료.** [실제 결과](human-comparison-results.md): 작업 구간 중앙값 A 40.27초, B 14.20초. 개발자 자동 조작과 별개의 자기 보고 참여 기록이며, 전체 SQL 분석의 시간 절감이나 새 사용자의 사용성 실험이 아니다.

## 비교할 작업

[실습 화면](../web/operations-practice.html)에서 이미 계산된 보고서 결과를 검토 표로 옮긴다. 두 방식의 원문·필드·행 수·대조 수준은 같다.

| 원문 규칙 | 건수 | 심각도 | 제출 상태 |
|---|---:|---|---|
| event_exact_repeat | 787170 | review | open |
| registration_missing_date | 45 | review | open |
| event_unknown_site | 0 | block | clear |

A는 건수와 심각도를 직접 옮기고 상태를 선택한다. B는 같은 데이터에서 세 필드를 자동 채운다. 두 방식 모두 각 행의 세 필드를 원문 및 `count > 0 → open, count = 0 → clear` 규칙과 대조하고 확인 상자를 선택한다. `clear`는 이 스냅샷에서 해당 규칙의 관측 건수가 0이라는 뜻이며 전체 데이터 품질 보증이 아니다. 이 단일 스냅샷 작업에는 상태 이력이나 resolved 전이가 없다.

보고서 바이트 SHA256: `675dfa6fa3126da0ba74b5a4b4c4222afff4d950297703f3314788f9135a30db`. 브라우저가 SHA를 확인한 후에만 시작할 수 있다. 데이터가 바뀌면 새 프로토콜로 검토해야 하며 해시 불일치를 무시하지 않는다. 전체 SQL 실행·원본 다운로드·문제 원인 조사·20개 규칙 검토는 이번 비교 범위에 포함하지 않는다.

## 참여자에게 첫 단계부터 안내

1. 배포된 `/operations-practice.html`을 연다. 이름·연락처를 입력하지 않는다. 실제로 직접 조작하는 사람은 “실제 참여자인 내가 직접 수행”을 선택한다. 장치, 처음 해보는 작업인지, 도움·방해가 있는지를 환경 칸에 쓴다. 본인이 수행했다고 선택한 사실은 기록되지만 신원은 인증하지 않는다.
2. 작업 범위를 읽고 확인 상자를 선택한다. A 연습의 “시작”을 눌러 원문을 확인하고 표를 채운다. 세 행을 대조하고 “완료”를 누른다. 누락이나 오류가 있으면 같은 연습을 다시 한다. B도 한 번 정확히 연습한다. 실패한 연습도 보존하되 시간은 기록하지 않는다.
3. 준비되면 측정 A → B → B → A → A → B를 진행한다. 각 회차 “시작”을 누르는 시점부터 “완료”까지 기록한다. 방해가 생기면 일시정지한다. 탭이 숨겨지면 자동으로 제외 구간에 들어가며, 돌아온 뒤 직접 “재개”를 눌러야 한다.
4. 측정 6회를 마치고 JSON을 내려받는다. 파일은 본인의 장치에 저장된다. 화면은 업로드·자동 저장·서버 기록 기능이 없다. 진행 중 새로고침하면 사라진다. 기록을 공유할지는 참여자가 선택한다.
5. 파일을 전달받았다면 아래 검사를 실행한다. 실제 파일과 환경 설명을 확인한 후에만 참여 기록을 갱신한다. 완료한 단계만 참여 기록에 반영한다.

```bash
python scripts/import_practice.py /path/to/operations-human_self_reported-....json
```

검사 스크립트는 파일을 읽고 표준 출력으로 일관성 검사 결과만 낸다. 업로드나 참여자 기록 저장을 수행하지 않는다. `--report`로 로컬 보고서 위치를 지정할 수 있다. 스냅샷 해시·원문 기대값, 정확히 6회 ABBAAB 순서, 성공한 연습 A/B, 필드별 누락/오류와 대조 확인, 시간 구간의 연속성·합계·음수/NaN·벽시계 차이를 검증한다. 기록의 신원·주의 집중·시계 조작 여부를 인증할 수는 없다.

## 시간과 품질의 해석

- `report_load_ms`: 최초 파일 읽기와 해시 검증의 기계 경과 시간. 반복 작업과 별도이며 다운로드만의 시간은 아니다.
- `task_interval_ms`: 사용자가 시작·완료·일시정지·재개로 조절한 active 구간의 합. **계측이 보장하는 집중 시간이나 실제 노동 시간이라고 부르지 않는다.** 일시정지 중 사고/읽기나 보이지 않는 방해를 알아낼 수 없다.
- `excluded_ms`: manual_pause·hidden 구간 합. `elapsed_ms = task_interval_ms + excluded_ms`. 각 구간과 시작/종료 시각을 보존한다. 탭에서 돌아온 뒤 재개 전 시간은 manual_pause다. 기기가 절전되거나 시스템 시계가 바뀌어 두 시계가 크게 어긋나면 검사가 기록을 거부한다.
- `machine_generation_ms`: B의 로컬 DOM 자동 입력 경과 시간. active 구간에 **이미 포함된 부분**이므로 더하지 않는다. 서버 분석 실행·SQL 대기·파이프라인 시간이 아니다. 브라우저 시계 해상도 때문에 0으로 보일 수 있다.
- 안내 읽기·설치·첫 학습은 반복 작업 측정 밖이다. 연습의 소요 시간은 측정하지 않는다. 나중에 필요하다면 별도 세션에서 재야 하며 이번 파일로 추정하지 않는다.
- 누락은 비어 있는 count/severity/status 필드 수(최대 9), 오류는 채웠지만 기대값과 다른 필드 수, 미확인은 대조 상자를 선택하지 않은 행 수(최대 3)다. 세 값이 모두 0인 회차만 유효하다. 잘못된 정수 형식/구조/변조된 점수는 가져오기 자체를 거부한다.
- 측정에서 잘못 입력한 회차를 몰래 재시도하지 않는다. 6회 결과에 그대로 남기며, 하나라도 무효이거나 출처가 developer_synthetic이면 `comparison_ready=false`다. `all_measured_rounds_valid`는 출처와 별개로 6회 출력의 유효성만 표시한다. 재측정은 별도 세션 전체를 수행하고 이유를 남긴다. 무효 회차를 제외하고 유리한 결과만 선택하지 않는다.
- 같은 데이터를 메모리에 로드해 재사용하므로 warm cache다. 반복으로 정답을 기억할 수 있다. ABBAAB는 각 방식 3회이며 위치 평균이 A 3.33회, B 3.67회로 완전한 순서 균형은 아니다. 무작위 배정·여러 참여자·새 데이터 과제가 없어서 학습/순서/캐시 영향을 분리할 수 없다.

원본 검증을 완료했더라도 “동일 장치에서 한 사람이 동일한 세 행을 반복 전사·대조한 구간의 중앙값 차이”까지만 기술한다. 사람의 실제 주의 시간, 전체 분석 자동화 시간, 월간 비용이나 회사 생산성 개선으로 일반화하지 않는다. 자기 보고 참여자 1명과 실제 사용자 모집 실험도 구분한다.

## 검증 기록과 남은 한계

`tests/test_practice_import.py`는 개발자 생성 fixture로 잘못된 count, 누락 필드, 대조 미확인, 해시 변경, ABBAAB 변경, 회차 누락, 중첩/음수/NaN/합계가 틀린 시간, 출처 누락을 거부하는지 검사한다. 정직하게 기록한 오입력/누락은 무효 회차로 보존한다.

`tests/practice_browser_check.py`는 실제 Chromium에서 개발자 자동 조작으로 연습·6회 측정·JSON 다운로드·오프라인 검증, 키보드 시작, 모바일 너비, 잘못된/빈 스냅샷과 복구를 검사한다. visibilitychange 경로는 합성 이벤트로 검증하며 실제 사람의 탭 이동이나 주의 관찰이 아니다. 이 스크립트의 임시 JSON은 `developer_synthetic`이며 검사 후 삭제된다. 실제 참여자 근거로 게시하지 않는다. 브라우저 자동화 성공은 처음 보는 사람의 이해도 검증과 다르다.
