# 실제 기기·화면 읽기 후속 검사

상태: 아래 후속 과제는 **아직 사용자 응답을 받지 않았다**. 기존 Safari·Android·VoiceOver 일부 과제는 [기기 기록](device-check-results.md)에 따로 남아 있다. 자동 브라우저 검사와 사람이 실제로 읽은 결과를 합쳐 한쪽 증거로 대신하지 않는다.

대상: 공개 데모의 3개 HTML 페이지와 메인 5개 작업 화면, 상세·표·오류·실습 상태. 전체 검토 범위는 [55개 기준표](accessibility-criteria.md)를 따른다. 사이트 밖 GitHub·논문·라이선스 사이트의 접근성은 이 프로젝트의 검증 대상이 아니며, 그 링크까지 이동할 수 있는지만 확인한다.

## 기록 방식

각 묶음을 안내받아 수행한 뒤 `수행 항목 / 실제 들린 말 또는 관찰 / 막힌 위치 / 도움`을 전달한다. 수행하지 않은 항목은 미실시, 기억나지 않거나 확인할 수 없는 항목은 모름으로 남긴다. 도구가 읽은 정확한 문구가 필요할 때는 들은 말만 적으며 기대 문구를 대신 쓰지 않는다. 기존 경험 여부·OS·브라우저·보조 기술 버전도 아는 범위만 기록한다. 각 과제를 한 번에 전부 요구하지 않고 아래 묶음별로 진행한다.

## A. Mac Safari 키보드·VoiceOver

VoiceOver 종료는 Command+F5(키보드 설정에 따라 Fn 함께)다. 기존 경험이 있는 지원자에게 안내하는 QA이며 독립적인 첫 사용자 사용성 실험으로 세지 않는다.

1. **지표 검토**: 첫 링크 `본문으로 이동`을 키보드로 실행하고 본문으로 이동하는지 확인한다. 검색 → 상태 필터 → 검토 항목을 이동한다. 동일값 반복을 열고 관측 근거·지표 영향·판단 기록을 좌우 방향키로 바꾼다. Tab으로 상세 본문에 들어갔을 때 초점 테두리와 제목·내용을 확인한다. SQL 원문 펼치기와 출처 링크까지 접근한다. 빈 검색 후 초기화로 돌아온다.
2. **재방문 근거**: 범위를 바꾼 뒤 분자·분모와 선택 범위가 맞게 읽히는지 확인한다. 차트에서 표로 전환해 열 제목과 첫 행의 관계를 읽는다. 개설기 검색의 빈 상태와 방법 설명 펼치기를 확인한다. 시각 차트의 정보가 표·텍스트로도 접근되는지 확인한다.
3. **실행 기록·검증 계획·생성 로그**: 실행 기록의 이슈 링크로 상세 화면에 이동한다. 검증 계획의 기준율·최소 차이 선택과 펼친 모집 표를 읽는다. 생성 로그의 관측·정리·지연·재수집 단계를 키보드로 바꾸며 가상 자료·재방문 분자/분모·품질 상태를 구분해서 읽을 수 있는지 확인한다. 모든 메뉴에서 Tab/Shift+Tab이 갇히지 않아야 한다.
4. **보조 데이터**: 이벤트 정의 3가지를 바꾸고 각 표의 제목·열·행을 읽는다. 품질, 결제, 관측 한계, 출처 목차 링크를 이용해 이동한다. 선택 상자의 현재 값, 실제 자료와 OULAD의 구분, 출처 링크가 읽히는지 확인한다.
5. **3개 규칙 실습의 오류**: 작업자는 `개발자·자동 테스트 (사람 측정 아님)`를 선택하고 환경에는 `접근성 QA`라고 입력한다. 이 기록은 수작업 비교의 실제 참여 회차에 섞지 않는다. 연습 A를 시작해 입력칸 이름에서 규칙과 필드를 구분할 수 있는지 확인한다. 일부를 비운 상태로 완료해 어떤 행·필드의 누락인지, 다시 연습하는 방법과 완료 기록 표를 읽는다. 측정 6회를 새로 수행할 필요는 없다.

각 번호는 별도 확인이다. 한 화면에서 제목을 읽었다고 다른 화면의 표·오류·완료 상태까지 통과 처리하지 않는다.

## B. 확대·재배치와 실제 Android

Safari의 보기 메뉴에서 페이지 확대를 200%와 400%로 설정한다. 모든 작업 화면과 보조 데이터·실습 준비 화면을 확인하고 100%로 복귀한다. 메뉴·제목·선택 상자·오류 설명·버튼이 잘리거나 겹치지 않아야 한다. 넓은 데이터 표·SQL은 해당 영역 안에서 스크롤할 수 있지만 페이지 전체의 불필요한 가로 이동과 구분한다. 브라우저의 실제 확대와 자동 검사에서 320px 폭 또는 CSS 글자 크기를 설정한 것은 다른 증거다.

Android에서는 세로·가로 화면에서 위 세 페이지의 이동·표 스크롤·확대와 터치 조작을 확인한다. 기존 Samsung Internet 결과는 해당 과제만 인정한다. TalkBack을 새로 검사하지 않았다면 검사했다고 쓰지 않는다. 새 보조 기술을 켜기 전 종료 방법을 확인한다.

## C. 실제 VoiceOver의 오류 안내·복구

정상 공개 사이트에 장애를 만들지 않고 로컬 전용 미리보기에서 첫 응답 한 번만 의도적으로 실패시킨다. 아래 서버는 `127.0.0.1`에서만 열리며 원본/집계 파일을 바꾸거나 외부로 전송하지 않는다. 데이터 누락을 복구하는 실제 회사 상황이나 실제 장애가 아니다.

업데이트된 프로젝트 폴더에서 실행한다.

```bash
python scripts/accessibility_preview.py --fault-once report.json
```

서버를 켠 터미널은 그대로 두고 Safari에서 `http://127.0.0.1:8767/`을 연다. VoiceOver로 파일 실패 안내와 재시도 버튼에 접근하고 재시도 후 제목·본문으로 이어지는지 확인한다. 서버는 Ctrl+C로 종료한다. 실습 페이지 검사 시에는 서버를 새로 켠 뒤 `/operations-practice.html`부터 열어야 첫 실패가 그 페이지에 적용된다.

다른 오류는 서버를 종료한 뒤 아래처럼 새로 켠다.

| 첫 응답을 실패시킬 파일 | 열 주소 | 확인할 내용 |
|---|---|---|
| `report.json` | `/` | 메인 오류·재시도·제목 초점 |
| `report.json` | `/operations-practice.html` | 실습 오류·재시도·진행 준비 초점 |
| `ednet_report.json` | `/external.html` | 보조 근거 오류·재시도·제목 초점 |
| `experiment-readiness.json` | `/?view=plan` | 실험 근거 오류·재시도·결과 영역 초점 |

예: `python scripts/accessibility_preview.py --fault-once ednet_report.json`. 브라우저 주소 오류 화면이나 인터넷 연결 실패만 보고 앱의 오류 안내까지 읽었다고 기록하지 않는다. 들린 오류·복구 후 위치를 실제로 전달받은 뒤에만 완료 처리한다.
