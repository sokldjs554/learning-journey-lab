# WCAG 2.2 A·AA 적용 범위와 확인 근거

2026-11-02 갱신. 이 문서는 **55개 A·AA 성공 기준을 빠짐없이 검토하기 위한 적용·근거 목록**이다. 전체 적합성 선언이나 접근성 인증이 아니다. 기준은 [W3C WCAG 2.2 권고안](https://www.w3.org/TR/WCAG22/)을 따른다. 2.2에서 삭제된 4.1.1은 55개에 포함하지 않는다. AAA 기준인 2.4.13 초점 모양 등도 이 목록의 판정 대상이 아니다.

범위는 `web/index.html`의 검토·재방문·실행·계획·생성 로그 화면, `external.html`, `operations-practice.html`과 이들의 HTML·CSS·JavaScript다. 데이터 계약 검사 코드와 카탈로그도 오류·동적 문구의 출처로 읽었다. 외부 GitHub·논문·라이선스 사이트와 내려받은 파일을 여는 외부 프로그램의 접근성은 범위 밖이다. 화면의 출처 링크에 도달하고 목적을 이해할 수 있는지는 범위에 포함한다.

## 근거를 읽는 방법

- **코드**: 현재 마크업·스타일·이벤트 처리와 기능의 존재 여부를 검토했다. 사람의 실제 읽기·발화 성공을 뜻하지 않는다.
- **브라우저**: 개발자가 Playwright/Chromium으로 실행한 합성 조작, 접근 가능한 이름·설명, 초점, 계산된 스타일 또는 axe 결과다. 운영체제 스크린 리더 음성을 확인한 결과가 아니다.
- **사람**: [지원자 직접 보고](accessibility-human-results.md)의 특정 과제에 한정한다. 안내형 QA이며 전체 기준의 적합성 판정을 뜻하지 않는다.
- **범위 경계**: 해당 증거가 지원하지 않는 조합·기능은 적합성 주장에서 제외한다. 자동 위반0건을 모든 사람의 읽기 성공으로 바꾸지 않는다.
- **비적용**: 현재 기능에 해당 조건이 없다. 새 기능이 생기면 다시 판단한다.

현재 직접 실행한 [연습 화면 회귀](../tests/practice_accessibility_check.py)는 7개 테스트가 통과했다. 초기 로드의 초점 유지, 재시도 성공·실패 초점, 규칙별 필드 이름, 9개 누락·3개 미확인 행의 설명, 잘못된 측정 회차의 잠금·내보내기 보존, 320px 완료 기록의 키보드 스크롤과 axe, 입력 경계 대비와 320px 문자 간격 확대 시 재배치를 확인한다. [기존 전체 연습 경로](../tests/practice_browser_check.py)도 axe를 켜고 통과했다. 이 자동 검사는 모두 `developer_synthetic`이다. 지원자의 별도 QA는 결과 문서에서 분리한다.

전체 화면·상태의 확장 브라우저 검사168조합은 [실행 결과](../reports/accessibility-complete-local.json)에 기록했다. 자동 위반·본문 넘침0, 문자 간격 확대 후 넘침0이다. [32개 키보드 순회](../reports/accessibility-keyboard.json)와 [초점·대비 회귀](../reports/accessibility-focus-contrast.json)도 통과했다. **실제 사람 확인 범위는 별도 결과 문서를 따른다.** 기존 [기술 검증 기록](verification.md)의 과거 결과와 이번 변경분의 결과를 구분한다.

[초기 기기 기록](device-check-results.md)과 [2026-11-02 확장 결과](accessibility-human-results.md)를 구분한다. 후속 보고는 주요 읽기·출처·메인/EdNet 재시도·확대·Android터치를 포함한다. 정확한 최신 버전·모든 화면의 읽기 순서·TalkBack·전체 적합성을 검증한 기록으로 확대하지 않는다.

## 사용자 확인 기록의 종료와 적용 범위

사용자 재확인을 종료하고 [실제 결과](accessibility-human-results.md)에 받은 근거를 정리했다. 위55개 기준은 적용·증거 범위표이며 전체 통과표가 아니다. 사람이 확인한 지정 읽기·조작·확대·터치와 개발자의 자동 검사 결과를 구분한다. Safari 배율은 자기 보고이며320px 자동 재배치의 측정값으로 바꾸지 않는다. 실습의 자동 복구 보고는 키보드 재시도 증거가 아니고, 검증 계획의 HTTP 오류 복구는 자동 브라우저 검사 근거를 사용한다. TalkBack·추가 기기 조합·독립적인 전체 이해도 평가·적합성 인증은 이 기록의 주장 범위 밖이다.

[사용한 절차](accessibility-human-checks.md)는 재현 참고용으로 보존한다. 추가 과제 수행을 요구하는 목록이 아니다.
