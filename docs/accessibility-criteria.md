# WCAG 2.2 A·AA 적용 범위와 확인 근거

2026-10-31. 이 문서는 **55개 A·AA 성공 기준을 빠짐없이 검토하기 위한 적용·근거 목록**이다. 전체 적합성 선언이나 접근성 인증이 아니다. 기준은 [W3C WCAG 2.2 권고안](https://www.w3.org/TR/WCAG22/)을 따른다. 2.2에서 삭제된 4.1.1은 55개에 포함하지 않는다. AAA 기준인 2.4.13 초점 모양 등도 이 목록의 판정 대상이 아니다.

범위는 `web/index.html`의 검토·재방문·실행·계획·생성 로그 화면, `external.html`, `operations-practice.html`과 이들의 HTML·CSS·JavaScript다. 데이터 계약 검사 코드와 카탈로그도 오류·동적 문구의 출처로 읽었다. 외부 GitHub·논문·라이선스 사이트와 내려받은 파일을 여는 외부 프로그램의 접근성은 범위 밖이다. 화면의 출처 링크에 도달하고 목적을 이해할 수 있는지는 범위에 포함한다.

## 근거를 읽는 방법

- **코드**: 현재 마크업·스타일·이벤트 처리와 기능의 존재 여부를 검토했다. 사람의 실제 읽기·발화 성공을 뜻하지 않는다.
- **브라우저**: 개발자가 Playwright/Chromium으로 실행한 합성 조작, 접근 가능한 이름·설명, 초점, 계산된 스타일 또는 axe 결과다. 운영체제 스크린 리더 음성을 확인한 결과가 아니다.
- **보류**: 현재 변경분에 대한 실제 보조기술·확대 검토 또는 확대된 브라우저 검사 결과가 아직 필요하다. 자동 위반 0건으로 보류를 해제하지 않는다.
- **비적용**: 현재 기능에 해당 조건이 없다. 새 기능이 생기면 다시 판단한다.

현재 직접 실행한 [연습 화면 회귀](../tests/practice_accessibility_check.py)는 7개 테스트가 통과했다. 초기 로드의 초점 유지, 재시도 성공·실패 초점, 규칙별 필드 이름, 9개 누락·3개 미확인 행의 설명, 잘못된 측정 회차의 잠금·내보내기 보존, 320px 완료 기록의 키보드 스크롤과 axe, 입력 경계 대비와 320px 문자 간격 확대 시 재배치를 확인한다. [기존 전체 연습 경로](../tests/practice_browser_check.py)도 axe를 켜고 통과했다. 모두 `developer_synthetic`이며 새 사람 측정은 없다.

전체 화면·상태의 확장 브라우저 검사168조합은 [실행 결과](../reports/accessibility-complete-local.json)에 기록했다. 자동 위반·본문 넘침0, 문자 간격 확대 후 넘침0이다. [32개 키보드 순회](../reports/accessibility-keyboard.json)와 [초점·대비 회귀](../reports/accessibility-focus-contrast.json)도 통과했다. **실제 사람 검토 대기는 별도로 유지한다.** 기존 [기술 검증 기록](verification.md)의 과거 결과와 이번 변경분의 결과를 구분한다.

[실제 기기·VoiceOver 기록](device-check-results.md)은 2026-10-30의 제한된 안내 과제에 대한 사용자 자기 보고다. Safari 16.6.1, Samsung Internet 30.0.5.27, VoiceOver의 재방문 제목·범위 선택·분자/분모 읽기만 포함한다. 현재 재시도·오류·초점 수정, 모든 화면의 읽기 순서, 확대, TalkBack까지 검증한 기록으로 확대하지 않는다.

## 현재 변경분에 남은 사람 확인

VoiceOver로 본문 바로가기→화면 제목→검토 상세 탭→SQL 출처→목록 복귀를 따라가며 현재 위치와 읽기 순서를 확인한다. 로드 오류 후 재시도 성공·재실패, 빈 검색 초기화, 연습의 규칙별 필드명·완료 오류 설명·다음 단계의 발화도 포함한다. 이 과제는 실제 응답을 받기 전까지 미실시다.

실제 브라우저 200% 문자/페이지 확대와 400% 페이지 확대에서 모든 화면의 주요 제어·설명·표 도달성을 확인한다. 320px 자동 재배치와 실제 확대를 같은 증거로 쓰지 않는다. Android TalkBack과 추가 기기 조합도 현재 기록으로 확인되지 않았다.

실제 후속 과제는 [단계별 기기 검사](accessibility-human-checks.md)를 따른다. 공개 배포 검증은 별도 결과를 받은 뒤 이 목록에 연결한다.
