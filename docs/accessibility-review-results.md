# 접근성 확장 검토 결과

2026-10-31. **개발자 기술 검사와 결함 수정은 수행했고, 현재 변경분의 실제 VoiceOver·확대 후속 응답은 대기 중이다.** 전체 접근성 완료·인증으로 표시하지 않는다. 범위는 [WCAG 2.2 A·AA 55개 기준표](accessibility-criteria.md), 사람에게 요청할 항목은 [실제 기기 과제](accessibility-human-checks.md)에 명시했다.

## 검사 범위와 결과

- 공개 HTML 3개와 메인 5개 화면: 검토 상세 3탭, 주요 규칙, 23개 분석 범위, 차트·표·빈 검색·펼침, 실행 기록, 모집 계획, 생성 로그 5단계, EdNet 정의3개, 실습 준비/A/B/무효/완료/일시정지/내보내기 상태.
- 로딩·HTTP 실패·잘못된 JSON·BLOCK·미확인 품질 상태도 포함해 **56개 상태 × 1440/390/320px = 168조합**을 Chromium141·axe4.11로 실행했다. 자동 위반0, 본문 가로 넘침0, 문자 간격 확대 후 본문 넘침0. [전체 상태·실행 당시 공개 파일 해시](../reports/accessibility-complete-local.json).
- 20개 규칙에서 상세 탭 키보드 전환, 23개 범위의 분모 문구, 3개 페이지의 본문 바로가기, 차트→표 접근을 확인했다. [동일 실행의 keyboard 항목](../reports/accessibility-complete-local.json).
- **32개 키보드 순회 조건**(8경로 × 2폭 × 펼침/접힘)에서 기대 제어와 실제 Tab 도달 수 일치, 화면 밖 초점과 표시 없는 초점 없음. 이는 Chromium의 조작·계산 스타일 검사이며 실제 VoiceOver음성이 아니다. [순회 기록](../reports/accessibility-keyboard.json).
- 재실패·복구 초점, 입력 경계 대비, 상세 패널 초점, SQL 영역 이름을 검사했다. [직접 회귀 기록](../reports/accessibility-focus-contrast.json). 실습 전용7개 회귀와 기존 전체 개발자 실습·내보내기 검사도 통과했다.
- 1280px에서 계산된 글자 크기를2배로 적용한7개 화면의 본문 넘침 없음. 확대 화면을 시각 검토했고 상태 선택의 잘림을 보완했다. [글자 크기 모의 검사](../reports/accessibility-text-resize.json). 실제 Safari의200%/400%페이지 확대와 동일하다고 주장하지 않는다.

자동 판정이 불완전한 항목도 버리지 않았다. 장식 로고/중복 화살표, 실습 textarea·가로 스크롤 표의 결과 셀, 빈 검색 표 머리글을 수동으로 분류했다. 계산된 대비는 준비 textarea21:1, 활성 결과 셀11.4570:1, 브랜드12.3045:1이다. 비활성 필드·장식의 예외와 실제 정보 텍스트를 구분한다. 판정 이유는 전체 JSON의 `manual_incomplete_review`에 남겼다.

## 발견과 수정

| 발견 | 재현된 수정 전 | 수정 후 |
|---|---|---|
| 파일 오류 뒤 재시도 | 주 화면·보조 데이터·실습·실험 근거에서 성공 후 BODY로 초점 유실 | 성공은 해당 제목/결과 영역, 재실패는 재시도 버튼으로 복귀 |
| 실습 입력 식별 | 모든 행에서 같은 건수/심각도/상태 이름 | 규칙 ID와 필드명을 연결한 접근 가능한 이름 |
| 실습 오입력 | 오류·누락 총수만 표시 | 해당 규칙·필드와 기준값을 설명하고 잘못된 상태 연결. 측정 입력 잠금·원래 점수 보존 |
| 실습 완료 표 | 스크롤 영역 이름·명시적 키보드 진입 부족 | 제목이 있는 영역·Tab진입·화살표 가로 스크롤 |
| 입력 테두리 | 본문·실습1.5885:1, 보조 데이터2.8682:1 | 세 곳 모두3.5366:1 |
| 상세 탭 패널 | 실제 Tab초점이 있지만 outline:none | 안쪽3px초점 테두리 |
| 320px 문자 간격 | 실습 fieldset 최소 너비로 본문338px | min-inline-size:0으로320px복귀 |
| 글자2배 상태 선택 | 고정104px열에서 선택 문구 잘림 | 내용에 맞는 열 너비, 선택 문구 확인 |
| 펼친 SQL의 영역명 | pre에 이름만 있고 이름을 받는 역할 없음 | 이름 있는 region으로 연결, 생성 SQL6개 영역 확인 |

실습 앞부분의 “사람 측정 없음”이라는 오래된 문구도 기존1인 실측 결과와 맞췄다. 기존 측정 점수·순서·JSON규격·분석 수치는 바꾸지 않았다.

검사 코드에서도 잘못된 가정을 바로잡았다. 닫힌 details 내부를 Tab대상에 포함했던 기준 목록을 고쳤고 펼침/접힘을 따로 검사했다. 실패 응답의 본문 완료를 기다리던 Playwright대신 실제 오류·초점 상태를 기다리도록 수정했다. 이들은 제품 결함 수정과 구분한다.

## 아직 완료하지 않은 부분

현재 변경분의 모든 화면에 대한 실제 VoiceOver읽기, 오류 알림의 실제 발화·이해, Safari실제200%/400%확대, Android회전·확대·터치 취소와 추가 보조기술 조합은 사용자 응답 전까지 대기다. 테스트에 경로가 있다는 사실을 사람이 수행한 결과로 쓰지 않는다. TalkBack등 모든 보조기술·모든장치 지원이나 인증을 선언하지 않는다.

공개 배포에서도 18개 자산의 저장소 바이트 일치, Chromium의 주요 동선·오류 복구, 8개 초점·대비 회귀와 32개 키보드 순회를 확인했다. 배포 직후 이전 파일 캐시로 실패한 기록과 갱신 후 결과는 [공개 배포 후속 기록](../reports/accessibility-deployed-followup.json)에 별도로 남긴다. 로컬 168조합과 배포 검사는 서로 다른 실행이며 실제 사람의 VoiceOver 응답을 대신하지 않는다.

소스 `95e8c205deaba7868d56bfda6df2c6035ab8abe1`의 [공개 브라우저 CI](https://github.com/sokldjs554/learning-journey-lab/actions/runs/41159827014)는 세 번째 실행에서 Chromium141·Firefox142·WebKit26 모두 통과했다. 첫 두 실행은 배포 직후 이전 자산이 제공되어 실패했으며 통과 기록으로 덮지 않았다. Chromium에서 공개 URL의 56상태 × 1440/320px = 112조합, 문자 간격 확대·키보드 추가 검사, 실습 전용 로컬 회귀7개를 통과했다. 공개 URL 검사와 로컬 실습 회귀를 구분한다.
