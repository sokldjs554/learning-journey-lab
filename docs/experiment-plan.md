# 다음 학습 진입점 실험 설계

**상태: 설계만 수행. 실제 서비스 노출·사용자 피드백·효과 측정 없음.**

## 왜 이 안을 먼저 검토하는가

첫 주 활동 빈도와 다음 주 활동의 관계는 전체·시간 분리·개설기 안에서 같은 방향이다. 반면 첫날 콘텐츠 접촉의 관계는 일부 개설기에서 반대다. 따라서 '콘텐츠를 더 보여주기'를 전면 도입하기보다, 계측을 고친 뒤 이미 학습을 시작한 사람이 다음 학습으로 돌아오는 동선을 실험 후보로 삼는다. 원래 학습 의지가 높은 사람이 자주 접속했을 수 있으므로 행동을 강제하면 같은 차이가 난다고 주장하지 않는다.

공개 서비스 안내에 이미 퀴즈·연속 수강 목표가 있다. '현재 기능이 없다'고 전제하지 않는다. 유료 수강 흐름을 직접 관찰하고 PM/디자이너와 현재 기능·카피·권한을 확인한 뒤, 중복되지 않는 최소 변화 하나를 확정해야 한다.

## 구체적인 가상 안

- 대상: 개별 구독의 신규 학습 계정, 첫 유효 학습 세션 종료 시점에 배정. 이미 실험 참여한 계정은 재배정하지 않음.
- 대조군: 확인된 현행 종료/내 클래스 경험.
- 실험군: 다음 학습 구간과 이어보기 진입점을 같은 위치에 명확히 제시하는 한 가지 UI 변화. 알림 발송을 함께 바꾸지 않음.
- 계측: assignment_id, experiment_id, variant, user_id, subscription_owner_id, eligibility_at, event_id, occurred_at, ingested_at, session_id, content_id, entitlement/version, app_version. 재생 진척은 백그라운드 재생/탭 전환/seek를 반영해 별도 정의.
- 배정 단위: 계정. 기기 간 동일 배정. 그룹 구독은 결제 주체·학습 주체와 간섭 구조가 달라 초기 실험에서 제외하고, 이후 결제 그룹 단위 군집 실험을 따로 설계.
- 층화 후보: 플랫폼, 첫 콘텐츠 유형, 신규/기존 구독 등 배정 전에 아는 속성. 사후 활동으로 배정하지 않음.

## 지표와 분석

서비스에서는 T0=첫 유효 학습 세션 종료·배정 시각으로 정의한다. OULAD의 개강일 D0와 다른 기준점이므로 분석 수치를 그대로 옮기지 않는다. 서비스 시간대(예: Asia/Seoul)와 일 경계를 계약에 고정하고 UTC 발생시각도 보존한다.

- 주요 지표: 모든 무작위 배정 계정 중 T0 기준 D7~13에 유효 학습이 있는 비율. 군별 분자와 모든 배정 계정의 분모를 보고하는 ITT. 화면을 실제 봤는지로 분모를 좁히지 않음.
- 메커니즘: D1~6 재학습, 이어보기 클릭, 유효 학습 세션. 보조 지표로만 해석.
- 가드레일: 재생 오류, 문의/불만, 환불, 알림 거부(관련 접점 존재 시), 장시간 강제 재생 의심 패턴. 계정당 콘텐츠 소비량 변화도 점검.
- 장기 관찰: 월/연간 구독 갱신, 결제 실패, 환불·권한 종료를 구분. 이번 단기 실험만으로 연간 구독 리텐션의 선행 지표가 확정되는 것은 아님.

양측 α=.05, 검정력 .8, 동등 배정, 고정 표본 2비율 정규근사. 필요한 표본은 `reports/report.json#/experiment/samples`에서 계산한다. 50% 기준율·+3%p는 **가정 시나리오**이며 실제 CLASS101 기준율이 아니다. 효과 예상값도 아니다. 기준율은 사전 서비스 계측으로 다시 추정하고 실질적으로 가치 있는 최소 차이를 PM과 합의한다.

## 운영·해석 기준

1. A/A 또는 내부 검증으로 배정 일관성·기기 간 동일성·이벤트 중복·수신 지연·소스 대조를 확인한다.
2. 모집 중 SRM과 양 군 계측 누락률 차이를 점검한다. 배정 비율 검정 경계와 알림은 사전에 고정하며 반복 검정에 의한 오탐을 고려한다. 운영 이슈 판단에 p값 하나만 쓰지 않는다.
3. 일일 적격 유입을 측정해 `ceil(2*n / daily_eligible)`로 모집 기간을 산정하고 적어도 완전한 주간 주기를 포함한다. 실제 유입량을 모르므로 완료 날짜를 만들어내지 않는다.
4. 마지막 배정자의 D13 관찰과 합의된 수신 지연 유예까지 기다린다. 중간 유의성에 따라 임의로 조기 종료하지 않는다.
5. 로그 손실·배정 오염·권한 변화가 있으면 효과 판정을 보류한다. 종료/재실험 여부는 영향 범위와 복구 가능성을 보고 정한다.
6. 효과 크기와 신뢰구간, 가드레일, 구현비용을 함께 검토한다. 유의하지 않음을 '효과 0의 증명'으로 해석하지 않는다. 부정적 결과도 보존한다.

## 결과를 얻지 못했을 때의 다음 학습

- 메커니즘은 변했지만 재방문은 그대로: 진입 마찰보다 콘텐츠 가치·시간 제약을 검토.
- UI 노출/이어보기도 변하지 않음: 조작이 충분했는지와 발견 가능성을 확인.
- 효과가 특정 플랫폼에만 존재: 사전 지정한 이질성 분석과 장애율을 확인하고 사후 선택적 성공 보고를 피함.
- 가드레일 악화: 전면 배포 대신 원인 조사. 이 자료에는 실제 사용자 인터뷰나 피드백을 포함하지 않았다.
