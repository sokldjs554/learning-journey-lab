## 개발 중 수정한 작은 오류

- SQL 별칭 `content`에서 파서 오류가 발생해 `has_content`로 수정; 손계산 지표 테스트로 회귀 확인.
- 초기 브라우저 실패 테스트가 Playwright route 콜백의 두 번째 Request 인자를 payload로 받아 테스트 자체가 실패. 인자를 명시적으로 분리하고 **이전 JS를 주입한 브라우저에서 5개 실패를 확인한 뒤** 수정 JS에서 6개 통과를 확인했다. 테스트 도구 오류를 제품 결함 증거로 세지 않았다.
- 전체 페이지 캡처 직전에 부드러운 스크롤이 진행돼 사이드바가 중간 위치에 기록됨. reduced-motion 및 즉시 스크롤, 별도 첫 화면 캡처로 교정. 제품 계산 결과에는 영향 없음.
- 이 환경의 기본 사용자 cache 경로에 브라우저/npm 설치가 실패해 작업용 `work/` 경로에 설치. 저장소 코드에는 개인 cache 경로를 하드코딩하지 않았다.

## 남은 불확실성

반복 행의 원천 의미와 탈퇴 후 활동 원인은 확인되지 않았다. OULAD에 없는 누락을 알아냈다고 주장하지 않는다. 강좌 일정·학습 동기·서비스 차이를 제거하지 못했다. 실제 사용자 관찰, 개선 실험, 구독 유지 측정은 후속 작업이다.

## UI 재설계 — 사용자 피드백 반영

사용자는 초기 UI가 전형적인 포트폴리오 대시보드에 가깝다고 지적했다. 공고의 로그 운영 업무와 9개 제품군·2개 디자인 체계를 다시 비교했다. 실제 CLASS101 직원의 피드백이나 사용성 실험은 아니다.

- 큰 제목·KPI·긴 스크롤 → 검토 목록과 선택 상세. 모바일은 목록/상세 이동으로 분리.
- 품질 규칙 20개가 모두 quality.sql로 연결 → 실제 SQL에서 규칙 ID와 행 위치를 추출. dimensions.sql의 6개 연결 수정.
- 개설기 선택 후 전체 콘텐츠 반례가 남음 → 같은 범위의 콘텐츠·활동일 지표 동기화. 시간 순서·최초 활동일 검증은 전체 범위에만 표시.
- 이슈 이력이 문서에만 존재 → 실제 issues.json과 benchmark.json을 검증해 operations.json으로 배포. 해시는 날짜가 아니라는 설명 유지.
- 선택 상태가 새로고침 때 사라짐 → URL에 화면·규칙·탭·개설기·실습 단계 보존. 뒤로가기·모바일 복귀 초점 검증.
- 기존 UI에서 새 검토 진입 테스트가 실패함을 확인한 뒤 구현. 이전 24개에 근거 묶음 정합성 테스트 5개를 추가.
- 자동 접근성의 색 대비 판정 불완전은 별도로 기록. 자동 0건만으로 완전한 접근성을 주장하지 않음.

수치가 맞는 테스트와 사용자에게 필요한 UI인지는 별개의 검증이다. 이번 개편의 사용성 개선 시간이나 성공률은 실제 사용자 연구로 측정하지 않았다.

별도 UI 코드 리뷰에서 보고서 실제 바이트와 실행 해시의 결합 누락, 모바일 브라우저 뒤로가기 초점, 선택 개설기 설명에 남은 전체 분모 수치를 발견했다. 회귀 4개를 수정 전 실패로 확인하고, 실제 응답 SHA256 대조·popstate 초점 복귀·전체 제외 내역 분리·0분모 비교 불가 처리를 추가했다. 기존 테스트가 잡지 못한 실패 가능성을 검증 범위에 포함했다.

공개 배포의 키보드 검사에서는 데이터 로딩 전 숨겨진 탭에 focus를 호출하는 테스트 오류를 발견했다. 응답을 0.8초 지연해 재현하고, 화면 준비 상태를 기다린 뒤 조작하도록 수정했다. 로컬·공개 주요 흐름을 다시 실행해 통과했다. 자동 접근성 27개 조합, 보고서 변형 12개, 리뷰 회귀 4개도 공개 주소에서 통과했다. 테스트의 준비 조건과 실제 제품 결함을 구분해 기록했다.

## 2026-10-30 KST: 실제 서비스 로그로 한계 축소

- 최초 가정: 결제 이벤트가 있는 공개 학습 데이터를 추가하면 구독 유지까지 설명할 수 있을 것이다. EdNet KT4의 실제 결제·환불 행을 확인했지만 가격·거래 ID·권한 장부·갱신 상태가 없어 매출/갱신 분석은 보류했다.
- 전처리 판단 수정: 플랫폼 결측 184행을 학습 로그 오류로 일괄 제외할 수 없다. 실제로 결제 173·환불 5·쿠폰 6행에 한정되어 이벤트별 계약으로 분리했다.
- 해석 수정: 첫 관측 후 14일 이상 활동한 사람만 남기면 관찰 기간이 해결되는 것처럼 보였으나 미래 활동으로 대상을 선택하는 편향이 생긴다. 1,761명의 관측 종료가 불명확하다는 한계를 유지하고 그 필터는 진단용으로만 표시했다.
- 재현 실패 가능성 수정: 다운로드 시각·전송량을 집계에 넣으면 같은 데이터도 보고서 해시가 달라진다. 이 값들은 로컬 감사 기록으로 분리하고 고정 선정 목록·콘텐츠·색인 해시를 검증했다. 감사 기록만 바꾼 두 실행의 최종 집계 해시 일치를 확인했다.
- 실험 기간 수정: D7~13은 마지막 배정 후 13일 대기가 아니다. 경과 시간 [7일,14일)로 명시하고 14일 관찰+수신 유예를 계산에 반영했다.
- 직접 참여: 사용자 테스트 작성·실측·처음 보는 참여자 사용성 검증은 실제 제출 전까지 미완료다. Codex 브라우저 자동 조작을 사용자 경험으로 대체하지 않았다.

## 2026-10-30 KST: 후속 문서 일치 검토
