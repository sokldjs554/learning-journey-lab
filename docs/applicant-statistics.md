## 손계산·경계·오류 검사

Codex가 작성한 **39개 검사 통과**:

- 생성 예시의 학습자 추출 `[A,A,B]`에서 A의 모든 수강 건이 두 번 기여하고 차이가2/3인 것을 확인. `[B,B,B]`는 한쪽 분모가 없어 제외되고 valid_draws에 포함되지 않음.
- 고정 seed로 학습자를 뽑은 뒤 **수강 행을 실제로 반복해서 펼치는 별도 계산**과 부트스트랩 구간·유효 횟수 대조. 행 순서 변경 및 같은 함수 재호출 결과 일치.
- 빈 집단·한쪽만 있는 집단·한쪽 학습자1명·모든 추출 무효에서 점 추정/null/valid_draws의 구분.
- 0일 활동의 다음 주 기록을 주 재방문율에서 제외하되 days 표에는 보존, 고유 사람 수와 수강 건수 구분, D6 비교 불가.
- 임계값과 같은 클릭의 포함, 10/20/50 경계, 빈 전환 셀, strict 키 재정렬과2일→1일의 변경 포함.
- 등록일 결측·개강 후 등록 등으로 mart에 없던2013년 등록자도2014년 재확인에서 제외. 2015년 자료를 두 시기 묶음에 넣지 않음.
- 빈 CSV의 정상 결과, 중복/결측/타입 오류·기본/strict 키 및 탈퇴일 불일치·DB 테이블/열 누락 거부.
- 반복 JSON·입력 해시, 읽기 전용 DB와 원본 보존, 출력 경로·심볼릭/하드 링크 충돌 차단.
- 계산 실패·비유한 결과·실행 중 입력 변경·저장 실패 때 기존 결과 보존과 임시 파일 정리. import만으로 분석·출력하지 않음.

초기 검토에서 Codex 테스트1개가 실패했다. 원인은 입력 변경 시의 `QualityRunError`를 테스트가 `ValueError`로 잘못 기대한 것이었다. 제출 코드는 의도대로 중단했다. 예외 정의와 CLI 처리 경로를 확인하고 **테스트의 기대 예외만 수정**한 뒤39개를 다시 통과했다. 이를 지원자 코드 결함이나 지원자의 수정 경험으로 기록하지 않는다.

## 보내준 명령과 재현

지원자가 전달한 사용 명령:

```bash
python run_statistics.py \
  --mart ./enrollment_mart.csv \
  --strict-mart ./enrollment_mart_strict.csv \
  --db ./oulad.duckdb \
  --output ./statistics.json
```

같은 직접 구현 폴더에 이번 두 파일과 재사용하는 이전 제출 모듈들이 있어야 한다. 해당 세 입력 파일이 실제로 존재하는 위치에서 실행하거나 경로를 바꾼다. 이번 메시지에 실행 출력은 없었으므로 그 경로의 존재나 사용자의 실제 실행 성공을 추정하지 않는다.

공개 저장소 최상위에서 Codex 검토 테스트는 다음과 같이 실행할 수 있다.

```bash
python -m pytest -q tests/test_applicant_statistics.py
```

실제 자료 통계 명령을 저장소에서 실행하려면 `python evidence/applicant/run_statistics.py`로 시작하고 위 입력 인자를 실제 경로로 지정한다. 기존 requirements 환경이 필요하다. 기존 [분석표 실행 안내](applicant-mart.md#재현)를 재사용할 수 있으며 원본을 덮어쓰거나 사람 실측을 다시 시작하지 않는다.

## 의미와 역할

지원자는 통계 계산·실행 코드와 사용 명령을 제출했다. Codex는 계약 안내·원본 보존·테스트 작성 및 수정·실제 자료 재실행·비교·문서·커밋을 담당했다. 별도 참고/도움 설명이나 설계 이유를 수신한 것으로 추가 기록하지 않는다. 코드 주석에서 기존 결과와의 재현 관계를 설명한 부분은 보존했다.

비율 차이와 군집 구간은 관찰적 결과다. 반복 수강을 고려해도 학습 의지·강좌 특성·개설 일정의 교란을 제거하지 못하고 CLASS101의 인과효과를 말할 수 없다. 시간 분리는 이미 공개된 자료의 재확인이며 실제 사전등록 실험이 아니다.

[고정한 남은 여섯 범위](applicant-completion-plan.md) 중 **통계·민감도의 제출·기능 검토를 완료**했다. 다음은 운영 연결이며 EdNet·생성 시나리오·UI·통합 검증/배포까지의 기존 범위는 유지한다. 전체 통합·배포 완료와 이번 모듈 검토 완료를 구분하고 새 기능·추가 사람 실측을 붙이지 않는다.
