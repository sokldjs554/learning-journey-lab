# 실험 설계에서 실행 계약 검사까지

**실제 서비스 A/B 실험은 미실시. 해당 실험 참여자 0명, 실제 재방문 효과 측정 없음.** 별도 데모 사용성 검토는 [전달받은 응답](usability-results.md)과 구분한다. 2026-10-29 UTC(한국 시각 2026-10-30) Codex가 구현하고 실행한 것은 합성 입력의 엔지니어링 검증이다. 공개 데이터의 추가 관찰 분석은 별도 자료이며 무작위 실험으로 바꾸어 부르지 않는다. 지원자가 직접 이 코드를 작성했다고 기록하지 않는다.

## 기존 계획에서 실제로 부족했던 부분

기존 `docs/experiment-plan.md`에는 대상·배정 단위·ITT·가드레일 후보·검정력 시나리오가 있었다. 다만 일 경계는 예시 시간대로만 남았고, 모집 기간은 식만 있었으며, 배정 오염·미성숙 분모·수신 지연·SRM 때문에 판정을 보류하는 규칙은 실행되지 않았다. 따라서 기존 OULAD 분석을 바꾸지 않고 다음을 추가했다.

| 기존 계획 | 이번에 실제로 보완한 것 | 아직 필요한 것 |
|---|---|---|
| D7~13과 서비스 일 경계 예시 | UTC 경과 시간 `[T0+7×24h, T0+14×24h)`로 고정; 초 단위 양끝·DST 반례 테스트 | 내부 지표 계약 승인 |
| 모든 배정 ITT 원칙 | 노출 이벤트가 전혀 없어도 배정 분모 유지; 미성숙은 0으로 채우지 않음 | 실제 배정 원장 및 누락 없는 소스 대조 |
| 배정·로그 문제면 보류 | 재배정/교차군/잘못된 키/결측/중복 충돌이면 `hold`, 배정 손상 시 군별 숫자도 숨김 | 서버 배정기·기기 간 일관성 검증 |
| 지연 유예 대기 | 발생 시각 watermark, 수신 시각 cutoff, 지연 초과와 watermark 모순 검사 | 실제 지연 분포와 완료 보증 |
| 모집 기간 식 | 기존 표본 6개를 독립 계산으로 대조하고 유입 3개를 조합한 18개 시나리오 실행 | 실제 적격 유입·기준율·최소 가치 차이 |
| SRM 반복 검정 고려 | 사전 지정 종료점 1회만 SRM; 중간 호출은 품질 확인만 하고 p값·차이값을 숨김 | 실제 사전 등록과 종료점 합의 |
| 가드레일 후보 나열 | 재생 오류/환불 계정 비율의 가상 허용 증가폭 검사 | 문의·권한 변경·소스 누락 등의 내부 가드레일 정의 |

## 대상·조작·제품과의 충돌

신규 개별 구독 계정의 첫 유효 학습 세션 종료를 T0로 한다. 계정당 한 번, 서버에서 1:1 배정하고 모든 기기에 같은 배정을 반환한다. 그룹 구독과 기존 실험 계정은 배정 전 제외한다. 이후 환불·구독 종료·미노출을 이유로 이미 배정된 계정을 ITT에서 빼지 않는다. 사후 권한 변화는 별도 안전성 검토이며 단순 무활동으로 원인을 단정하지 않는다.

대조군은 실제 현행 종료/내 클래스 화면, 실험군은 같은 위치의 다음 학습 구간·이어보기 문구와 진입점 **한 가지 변경** 후보다. 알림·자동 재생·보상·추천 알고리즘을 함께 바꾸지 않는다. 유료 화면에 접근해 실제 현행 UI를 관찰하지 못했으므로 아직 구현 가능한 최종 화면 실험이라고 주장하지 않는다. PM/디자이너가 현행 화면과 기능 중복을 먼저 확인해야 한다.

2026-10-29 UTC(한국 시각 2026-10-30) 공식 도움말을 새로 열어 확인한 내용은 `reports/service-guidance-check.json`에 남겼다.

- [CLASS101+ 구독 안내](https://help.class101.tv/classmate/class101-plus-subscription-guide): 퀴즈·연속 수강 목표가 이미 안내되어 있고 크리에이터 계약 종료로 콘텐츠 제공이 바뀔 수 있다. 새로운 습관 형성 기능이 없다는 전제로 제안하지 않는다.
- [수강 방법](https://help.class101.tv/classmate/how-to-take-class): PC는 프로필/마이페이지의 내 클래스, 모바일은 하단 내 클래스 경로가 안내되어 있다. 내 클래스 진입점을 새로 만드는 안으로 표현하지 않는다.
- [그룹 구독](https://help.class101.tv/classmate/class101-group-plan): 결제·환불 담당 대표 계정과 초대된 학습 계정이 구분된다. 학습 계정의 재방문을 결제 계정의 갱신으로 해석하지 않는다.

세 페이지에는 AI 자동 번역 고지가 있다. 가격·콘텐츠 수·초대 제한 등의 번역 문구를 실험 수치의 근거로 쓰지 않는다. 공식 안내의 존재는 확인했지만 로그인 후 현재 UI·실제 사용 행태를 확인한 것과는 다르다.

## 실행 가능한 입력 계약

`src/journey/experiment_readiness.py`는 외부 서비스에 접근하지 않는 작은 표준 라이브러리 검사기다. 실제 사용자 기록을 만들거나 배정하지 않는다.

배정 원장은 `experiment_id, assignment_id, user_id, variant(control/treatment), assigned_at`을 가진다. 실험당 사용자와 assignment_id는 각각 유일해야 한다. 모집 구간은 `[enrollment_start, enrollment_end)`이다. 중복 원장은 조용히 제거하지 않고 보류한다. 가입·상품·신규 여부 등 적격성은 상류에서 확정해야 하며 이 최소 모듈이 검증했다고 주장하지 않는다.

이벤트는 같은 실험/배정/사용자/군 키에 `event_id, kind, occurred_at, ingested_at`을 더한다. `kind=learning`은 원시 재생 버튼이 아닌, 사전에 검증된 **유효 학습 이벤트**를 뜻한다. 전경 재생·seek·백그라운드·최소 진척·세션 종료 등 생성 규칙은 실제 계측 전 확정해야 한다. 현재 모듈은 학습 판정 알고리즘을 대신 구현하지 않는다. 최소 계약의 종류는 `learning, exposure, playback_error, refund`뿐이다. 동일 event_id의 동일 행은 재전송으로 1회 처리하고 내용이 다르면 보류한다. 배정 전 이벤트·수신이 발생보다 이른 이벤트·미등록 키·결측 시각은 보류한다. 타 실험 행은 입력 전 필터해야 하며 섞이면 검사 실패다.

모든 시각은 timezone-aware 값이어야 하며 계산 전에 UTC로 변환한다. 달력 날짜 D7이 아니다. T0가 1월 1일 12:00 UTC라면 관찰 창은 1월 8일 12:00 포함~1월 15일 12:00 제외다. D13의 마지막 순간까지 보려면 **T0+14일이 지나야** 한다. 기존 계획의 'D13 관찰 후'를 T0+13일 종료로 읽지 않도록 명시했다.

`watermark`는 해당 발생 시각 **미만**의 로그가 수집·대조 완료됐다는 외부 보증이다. 마지막 관찰 끝 이상으로 올라와야 한다. `as_of`는 보고서가 알고 있던 수신 시각의 cutoff다. 발생이 관찰 창 안이더라도 이후에 수신되는 행을 과거 보고서 분자에 넣지 않는다. 완료됐다고 선언한 구간에 아직 미수신 행이 알려져 있으면 watermark 모순으로 보류한다. 관찰 끝+지연 유예가 지나기 전, 실제 관측된 지연이 가상 유예 1일을 넘을 때도 보류한다. 완료 보증이 거짓이거나 **아예 제공되지 않은 로그는 검사기로 발견할 수 없다**. 운영 원천 건수·오류율·수집 파이프라인 상태의 대조가 별도 필요하다.

분모는 배정된 모든 계정이다. 중간 품질 조회에서는 `assigned`와 `matured`를 함께 보이고 완전히 관찰된 계정만 잠정 비율을 계산한다. 미성숙을 실패로 세지 않고 최종 차이를 숨긴다. 최종 판정은 모든 배정 계정이 성숙한 시점만 허용하므로 성숙 분모와 전체 배정 분모가 같다. 탈퇴·미노출 계정도 포함된다. 실제 계정 삭제로 이벤트를 확보할 수 없다면 단순 0으로 처리하지 말고 소스 완전성 판정을 보류해야 한다.

## 보류 기준과 해석

- 배정 손상: `arms=null, difference=null, status=hold`. 그럴듯한 숫자로 잘못된 실험을 보고하지 않는다.
- 이벤트 품질·미성숙·지연·표본 부족: 진단용 군별 수치를 남기되 `difference=null`이다.
- SRM: 종료점 **한 번**, 전체 배정 수로 1:1 Pearson χ²(df=1), `p<.001`이면 보류한다. 기대 빈도 5 미만인 작은 합성 사례는 양측 정확 이항 검정으로 계산한다. `.001`은 실제 회사 기준이 아닌 가상 사전 고정값이다. 일일 대시보드에서 같은 검정을 반복해 중지 여부를 고르는 설계가 아니다. `checkpoint='interim'`은 SRM p값과 차이를 출력하지 않는다. 운영 중 명백한 배정 오류는 유의성과 무관하게 즉시 조사한다.
- 가드레일: D0~13 `[T0,T0+14d)`에 재생 오류/환불을 한 번 이상 가진 계정 비율을 모든 성숙 배정 계정으로 나눈다. 실험군−대조군 증가가 **가상 +1%p 초과**이면 보류한다. 정확히 한계이면 통과다. 이는 통계적 안전성 입증/비열등성 검정이 아니며 작은 표본에서 차이가 없다고 안전하다고 말할 수 없다. 실제 허용폭과 신고·불만·권한 로그는 사전 합의가 필요하다.

`ready_for_review`는 입력 계약상 차이를 검토할 수 있다는 뜻이다. 전면 배포 승인도 인과 효과의 증거도 아니다. 단순 차이만 산출하며 실제 효과 검정·신뢰구간·층화·다중성·장기 갱신 분석을 수행하지 않는다. 실제 실험에서는 사전 등록된 효과 추정·신뢰구간과 가드레일 검토가 뒤따라야 한다.

## 표본과 모집 기간: 모두 가정

기존 `reports/report.json`의 양측 α=.05, 검정력 .8, 1:1 2비율 정규근사 표본을 표준 라이브러리 `NormalDist`로 독립 계산해 6개 모두 일치함을 확인했다. 계산식은 `ceil([(z.975√(2p̄(1−p̄))+z.8√(p1(1−p1)+p2(1−p2)))/Δ]²)`다.

`raw=ceil(2n/일일적격유입)`, `모집일수=max(7,7×ceil(raw/7))`, `완료일수 상한=모집일수+14+지연유예1일`이다. 전체 주간 주기를 포함하는 보수적 상한이며 마지막 배정의 실제 시각에 따라 정확한 종료 시각이 정해진다. 모든 유입이 적격하고 예상 배정량이 확보된다는 가정이다. 아래는 +3%p 시나리오 일부이며 나머지 +5%p를 포함한 18개는 JSON에 있다.

| 가상 기준율 | 군당 목표 | 가상 일일 적격 유입 | 주간 단위 모집 | 관찰·유예 포함 상한 |
|---|---:|---:|---:|---:|
| 30% | 3,763 | 100 | 77일 | 92일 |
| 50% | 4,356 | 50 | 175일 | 190일 |
| 50% | 4,356 | 100 | 91일 | 106일 |
| 50% | 4,356 | 500 | 21일 | 36일 |
| 70% | 3,554 | 100 | 77일 | 92일 |

실제 CLASS101의 기준율·일별 유입·예상 효과가 아니다. 특히 수개월짜리 시나리오에서는 상품·시즌 변화가 커서 사전 유입 측정 후 범위·MDE·실행 가능성을 재검토해야 한다. 모집 시작/끝과 유일한 최종 조회를 실행 전에 고정하고, 주간 반올림으로 목표보다 많이 배정되면 모두 ITT에 넣는다. 목표 미달이면 효과 보고를 보류하며 p값을 본 뒤 모집을 연장하지 않는다. 따라서 여기서 표본 수는 고정 종료 구간에서 확보해야 할 **최소 군당 목표**다.

## 재현과 실제 확인 결과

```bash
python scripts/check_experiment.py
python -m pytest -q tests/test_experiment_readiness.py
```

`reports/experiment-readiness.json`에는 합성 20계정의 정상 계약, 교차군 배정 오염, 지연 도착 사례와 가정 모집 표가 저장된다. 정상 사례는 10명씩 배정해 각 3명 재방문하도록 직접 만든 입력으로 차이 0을 계산한다. 이 수치를 서비스 결과·사용자 피드백으로 인용하면 안 된다. 38개 테스트에서 초 단위 경계, DST, 중복, 결측, 잘못된 키, 미성숙, SRM 불균형, 종료점 이전 실행, 가드레일 경계, 잘못된 설정을 검사했다.

실제 참여자 모집 채널·접근 권한·실험 시스템·서비스 원장과 로그가 없다. 따라서 이 문서는 사용자 검증의 대체 성과가 아니며 실제 실험은 미실시로 유지한다. 기존 설계의 구체성과 실패 검출 가능성을 실제 코드·반례 테스트까지 높인 보완이다.
