## 2. 실제 데이터 조사와 선택

EdNet KT4/KT1, Junyi 2018–2019, KKBox, HarvardX/MITx를 공식 자료로 조사했다. KT4는 문제 제출·화면 진입·구매·환불이 함께 있어 이벤트 의미를 비교할 수 있었고 실제로 확보했다. KT1은 더 제한된 응답 정보, Junyi는 무료 교육 서비스이며 구독 필드 부재, KKBox/HarvardX는 이번 접근에서 이용 조건·파일을 충분히 검증하지 못해 제외했다. [기간·스키마·접근·라이선스 표](data-sources.md). OULAD는 보존하고 두 자료를 합산하지 않았다.

## 3. 추가 실제 분석

EdNet KT4 CC BY-NC 4.0, 공식 사용자 파일의 사전 해시 표본 **2,048명 / 854,678행**을 확보했다. 전체 제공 사용자 파일을 사용했고 분석 결과만 공개한다.

- 첫 관측 이후 첫 주 문제 제출이 1개 24시간 구간에 있는 사람: 다음 주 제출 기록 **31/1,688 = 1.84%**.
- 2개 이상 구간: **135/342 = 39.47%**. 관찰 차이 +37.64%p, 95% 부트스트랩 구간 +32.13~+42.86%p.
- 모든 이벤트를 활동으로 세면 첫 주 2개 이상 여부 **23명**, 다음 주 기록 여부 **14명** 변경. 반복 초과 **1,519행**을 제외해도 활동 지표 변경 **0명**.
- 플랫폼 결측 **184행**은 구매173·환불5·쿠폰6에 한정. 학습 플랫폼 누락으로 일괄 분류하지 않았다.
- 실제 구매 **173행/164명**, 환불 **5행/5명**. 가격·거래 ID·권한·갱신 필드가 없어 매출·갱신율은 계산하지 않았다.

첫 관측일은 가입일이 아니며, **1,761명의 14일 이후 무기록을 이탈로 확정할 수 없다**. 관측 종료·시간 이동·표본·학습 의지 등 한계를 남겼다. CLASS101 효과나 OULAD보다 높은/낮은 리텐션이라고 비교하지 않는다. [방법·분모·제외·민감도](ednet-analysis.md).

## 4. 실험과 사용자 검증

요청의 B 방식인 실제 공개 데이터 관찰 검증을 수행했다. 실제 서비스 A/B 실험은 **미실시, 실험 참여자 0명**이다. 별도 데모 사용성 검토는 이후 1명의 네 과제 응답을 진행자를 통해 받아 [결과와 문구 수정](usability-results.md)을 기록했다. 수정 후 참여자 재검토는 아직 미실시다. 합성 20개 배정의 입력 검사는 실제 참가자 모집이 아니다. [실험 계획](experiment-plan.md)과 [입력·모집 검증](experiment-readiness.md)을 구현했다. 실제 기준 재방문율·유입량·계측 원장은 여전히 필요하다.

## 5. 자동화 비교

같은 보고서·규칙·3개 결과·검토 수준으로 A 수동 입력, B 자동 입력을 비교했다. 지원자가 연습 2회와 ABBAAB 측정 6회를 수행하고 JSON을 제출했으며 Codex가 원본 일관성을 확인했다. 작업 구간 중앙값은 **A 40.27초 / B 14.20초**, 관측 차이 **26.06초**다. 오류·누락·미확인은 양 방식 모두 0건이다. 첫 A의 제외 378.02초를 유지했다. 1인 반복·학습·순서·중간 코드 실습의 영향을 분리하지 못하며 전체 SQL 분석이나 회사 생산성 절감이 아니다. [실제 결과와 재현](human-comparison-results.md).

## 6. 지원자의 직접 참여

기존 결과 읽기·369건 해석·개설기 반례·손계산·Actions 수동 실행은 대화/실행 기록으로 확인했다. 사용자는 제공 예제를 테스트 파일로 추가하고 **4996ef6으로 직접 커밋**했다. Codex가 브랜치 CI 성공과 최신 코드 통합 후 115개 테스트 통과를 확인했다. 예제 설계·검증 도움과 파일 추가·커밋의 직접 수행을 구분한다. 조사·추가 분석·UI·코드·검증·배포는 Codex 작업이다. [참여 기록](participation.md), [작은 코드 작성 단계](portfolio-evidence.md#직접-코드-작성-안내).

## 7. UI 변경

기존 검토 목록·상세·재방문 근거 구조를 유지했다. 분자/분모를 모든 범위에서 문장으로 설명하고 369는 정책별 수강 건 분류 차이라고 표시했다. 콘텐츠 비교의 %p와 인과 한계, 9개 반대 방향 중 8개 구간이 0을 포함한다는 설명을 추가했다. 보조 데이터는 별도 출처·분모·이벤트 전환·오류 복구 화면으로 연결했다. 실제 서버 분석이 없는 정적 도구임을 화면에 유지한다.

## 8–9. 배포와 반복 검증

## 11. 남은 한계

- 실제 CLASS101의 관측·구독·매출 정보와 무작위 처치가 없어 인과효과·사업 성과는 확인하지 못했다.
- EdNet의 관측 종료·신규 가입·실제 달력일을 복원할 수 없다. 실제 데이터 확보로 이 한계가 해소되지는 않는다.
- 직접 테스트 추가·커밋 및 실측 6회·전체 JSON 제출을 확인했다. 새 사용자 검토와 일반화 가능한 추가 비교는 필요하다. 이전의 안내받은 실습을 새 사용성 평가로 재분류하지 않았다.
- Chromium의 PC/모바일 크기에서 확인했다. 실제 모바일 기기·Safari·Firefox·스크린 리더 사용자 검증은 하지 않았다. axe 자동 탐지 위반 0은 완전한 접근성 보장이 아니다.

## 12. 사실대로 활용할 범위

구현 사실로는 “두 실제 공개 학습 자료에서 데이터·이벤트 정의에 따라 판단이 달라지는 범위를 분석하고, 독립 계산과 재현 검사를 구축했다”를 사용할 수 있다. 본인 경험으로는 **“Codex의 안내를 받아 분모·처리 민감도·반대 근거를 확인하고 전체 분석을 Actions에서 직접 재현했다”**가 현재 확인된 범위다. 독립적으로 전체 코드 작성, 사용자 피드백 수집, 시간 절감, 리텐션·매출 개선은 주장하지 않는다. 제공 예제의 테스트 추가·커밋은 직접 수행에 추가할 수 있으며, 독립 설계로 표현하지 않는다. 안내에 따른 1인·각 3회 검토표 기록 측정과 원본 제출도 직접 수행한 사실에 포함할 수 있다.
