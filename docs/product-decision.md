# 재방문 개선의 선택 조건

작성·공식 도움말 재확인: 2026-11-02 UTC, Codex. **제품 가설 비교이며 실제 CLASS101 사용자 행동 관찰이나 기능 실험 결과가 아니다.**

## 현재 결정

클릭 임계값에 따른 성공 판정은 보류하고 활동일을 관찰 지표로 사용한다. 다음 학습 안내는 **조건부 실험 후보**다. 활동일과 재방문의 관계만으로 안내의 불편을 발견했다고 결론내리지 않는다. 현재 근거로 우선 확정할 일은 로그·권한 점검과 현행 동선 관찰이며, UI 배포는 아직 결정할 수 없다.

OULAD에서 1일군 3,835/5,565=68.9%, 2일 이상군 16,468/17,957=91.7%다. 차이 +22.8%p는 관찰 집단 차이이지 UI의 예상 효과가 아니다. 콘텐츠 접촉은 전체 +1.5%p지만 22개 개설기 중 9개에서 반대여서 무조건 노출을 늘리는 근거가 되지 않는다. 이 수치는 `reports/report.json`과 기존 분석 계약을 따른다.

## 같은 결과를 설명할 수 있는 대안

| 설명 후보 | 현재 근거 / 비어 있는 근거 | 필요한 관찰 | 후보를 낮추거나 바꿀 조건 | 다음 액션 |
|---|---|---|---|---|
| 기록 누락·권한/재생 장애 | 공개 자료에서 반복·키·기간 문제 관측. 실제 회사 장애는 미관측 | 원천 대조, 재생 요청/성공/오류, entitlement 판정과 콘텐츠 제공 기간 | 기록이 완전하고 실패 접점이 드물면 장애 중심 설명을 낮춤 | 문제가 있으면 UI 실험보다 계측/장애 수정 우선 |
| 다음 학습 진입 마찰 | 활동일과 재방문 관계는 일관된 방향. 진입 경로·클릭·실패 로그 없음 | 종료 화면 노출→다음 구간 발견→진입→유효 학습, 동의받은 과제 관찰 | 다음 학습을 쉽게 찾지만 학습하지 않는다면 진입점 변경을 보류 | 기존 화면에서 발견/진입 마찰이 확인될 때 한 가지 안내 변경 |
| 콘텐츠 적합성·난이도 | 콘텐츠 접촉의 관계가 개설기마다 다름. 내용·난이도·만족도 미관측 | 콘텐츠 유형·진도·학습 목적별 패턴, 중단 이유, 관련 문의 | 같은 콘텐츠 안에서 진입 오류가 주된 원인이면 콘텐츠 확대보다 동선/기술 조사 | 특정 콘텐츠군의 문제라면 범위를 제한해 개선; 전면 노출 확대 보류 |
| 시간·재료 준비 제약 | 창작 학습에 가능한 설명. 공개 도움말상 재료 별도 구매; 실제 원인 빈도는 모름 | 학습 목적·가능 시간·재료 준비 여부를 중립적으로 질문, 수업 길이와 간격 관찰 | 시간/재료 문제가 없다는 응답·행동 근거가 쌓이면 우선순위 하향 | 짧은 구간·준비 안내 후보. 알림을 자동으로 해법으로 삼지 않음 |
| 원래의 학습 의지·계획 | 사전 의지가 빈번한 활동과 재방문 모두를 만들 수 있음 | 배정 전 목적/경험/구독 유형, 시간 분리 분석; 최종적으로 무작위 실험 | 안내 클릭만 늘고 재방문이 변하지 않으면 지표와 효과의 연결 재검토 | 활동일을 늘리면 자동으로 유지가 오른다고 주장하지 않음 |

## 실험 우선순위를 정하는 절차

1. **관측 가능성:** 누락·배정·권한 오류가 결과를 뒤집을 수 있으면 효과 판단을 보류한다.
2. **문제 위치:** 현행 종료/내 클래스 흐름에서 실제로 다음 구간을 못 찾는지 확인한다. 유료 화면을 직접 본 것처럼 쓰지 않는다.
3. **대안 비용:** PM/디자이너/개발자가 기존 컴포넌트 재사용, 기기별 변경, 계측 추가, 권한 위험을 확인한다. 지금은 공수·유입·예상 효과를 모르므로 숫자 점수로 순위를 꾸미지 않는다.
4. **선택:** 진입 마찰이 확인되고 작은 한 가지 변경으로 분리 가능할 때만 안내 A/B를 진행한다. 그렇지 않으면 위 표에 따라 장애·콘텐츠·시간 제약 문제로 전환한다.
5. **판단:** ITT 재방문 효과와 불확실성, 가드레일, 비용을 함께 본다. 이어보기 클릭 상승만으로 확대하지 않는다. 연간 갱신은 별도 추적한다.

### 필요한 최소 관찰 과제

권한 있는 실제 학습자가 현재 화면에서 학습을 마친 후 다음에 공부할 구간을 찾도록 한다. 진행자는 정답 동선을 먼저 알려주지 않고, 멈춘 위치·오류·도움·참여자의 실제 이유를 기록한다. 목적은 마찰의 존재와 기전을 찾는 것이며 몇 명의 관찰을 전체 사용자 비율로 일반화하지 않는다. **이번에 이 서비스 과제를 수행하거나 모집한 사람은 없다.** 기존 데모 참여자 피드백은 분석 도구 이해도 검토이며 이 관찰을 대체하지 않는다.

## 공식 서비스 안내와 설계의 관계

- [수강 방법](https://help.class101.tv/classmate/how-to-take-class): PC/모바일의 내 클래스 경로가 존재한다. 새 경로를 발명했다고 표현하지 않는다.
- [구독 안내](https://help.class101.tv/classmate/class101-plus-subscription-guide): 연간 이용, 기존 학습 지속 기능, 구독 제외 상품·콘텐츠 제공 변경·재료 별도 구매가 안내되어 있다. 결제 할부와 구독 갱신을 구분해야 한다.
- [그룹 구독](https://help.class101.tv/classmate/class101-group-plan): 결제 관리 계정과 초대된 학습 계정이 다르다. 학습 계정 수를 갱신 분모로 쓰지 않는다.

세 페이지에는 AI 번역 고지가 있었다. 공개 문구는 구조를 확인하는 근거이며 정확한 청구·환불 정책의 실행 명세나 현재 로그인 UI의 실관찰이 아니다. 가격·공수·사용자 수를 추정하지 않았다.

실험 입력·통계 계획은 [기존 실험 설계](experiment-plan.md), 학습과 갱신을 연결하기 위한 SQL 계약은 [구독 연결](subscription-bridge.md)을 따른다.
