## 구현에서 확인한 내용

SQL은 전체와 강좌·개설기별로 첫 주 활동을 1일/2일/3일 이상으로 나눈다. 입력에 존재하는 개설기와 세 그룹을 먼저 만들고 집계를 연결하므로 활동이 없는 그룹도 분모0·분자0·비율NULL로 남는다. 전체 행과 개설기 행을 합쳐 이중 계산하지 않는다.

Python은 앞서 제출한 분석표 검증과 JSON 저장 함수를 재사용한다. CSV를 메모리 DuckDB에 적재하면서 Python으로도 그룹별 건수를 계산하고, SQL의 각 행과 대조한다. 전체 합계가 맞아도 그룹별 값이 틀리면 거부한다. 실행 전·후 입력 해시를 확인하고, 출력은 검증에 성공한 뒤 교체한다. 이 단계에서 원천 로그 품질 판정을 새로 생성하지 않는다.

## 실제 자료 대조

앞서 제출한 원본 검증·적재·분석표 코드로 실제 OULAD의 기본/strict CSV를 각각 새로 만들었다. 각 CSV에서 이번 집계 Python을 두 번 실행했다. Codex가 별도 Python csv·정수 합계·Decimal 반올림으로 계산한 69행과 비교했다. 이 대조는 제출 Python 안의 자체 대조와 별도로 수행했다.

| 정책 | 적격 수강 건 | 첫 주 활동 | 그중 다음 주 활동 | 재방문율 | 비교 행 | 불일치 |
|---|---:|---:|---:|---:|---:|---:|
| 기본 | 29,671 | 23,522 | 20,303 | 86.3% | 69 | 0 |
| strict | 29,671 | 23,430 | 20,210 | 86.3% | 69 | 0 |

두 비율은 소수 첫째 자리 표시가 같지만 분자·분모가 다르다. strict는 활동 기간 정책의 민감도 비교이며 분모인 적격 수강 건은 유지한다.

기본 정책의 전체 그룹 결과는 다음과 같다.

| 첫 주 활동 | 분모 | 분자 | 재방문율 |
|---|---:|---:|---:|
| 1일 | 5,565 | 3,835 | 68.9% |
| 2일 | 4,803 | 3,992 | 83.1% |
| 3일 이상 | 13,154 | 12,476 | 94.8% |

기본 69행은 제출 전에 공개한 [대조 자료](../reports/applicant-aggregate-reference.json)와도 일치한다. 각 정책의 같은 입력 반복 실행 JSON 바이트가 같았다. 실제 원본·manifest·제출 코드·입력 DB·CSV의 해시와 수정 시각은 유지됐으며 학습자 수준 CSV는 공개 저장소에 올리지 않았다.

## 손계산·오류 검사

Codex의 **52개 검사 통과**:

- 이전에 지원자가 손계산한 8행을 분석표 형식으로 변환해 전체 첫 주 활성7·재방문4·57.1% 및 그룹별 50.0/50.0/66.7% 확인. 추가 분석표 필드는 Codex가 테스트용으로 채웠다.
- 헤더만 있는 입력의 전체 빈 그룹3행, 첫 주 활동이 전혀 없는 개설기의 빈 그룹 유지, 첫 주0일의 다음 주 활동 제외.
- 같은 학습자가 여러 강좌·개설기에 존재할 때 수강 건별 집계, 개설기 복합키와 정렬, 누락된 그룹 처리.
- 1/16=6.25%를 6.3%, 3/16=18.75%를 18.8%로 표시하는 반올림 경계.
- 같은 입력 반복 JSON 일치. CSV 행 순서를 바꾸면 집계·overall은 같고 input_sha256은 변경된 바이트를 반영.
- 키 결측·중복, 정수 형식·활동 범위·클릭 모순, 헤더/열 오류 거부.
- SQL 결과 누락·중복·범위/그룹/개설기 오류, 음수·소수·불리언 건수, 잘못된 그룹별 값·비율·NaN·빈 그룹 비율0을 거부.
- 누락·빈 SQL·SQL 오류·저장 실패·입력/출력 경로 및 심볼릭 링크 충돌·실행 중 입력 변경에서 실패 처리와 이전 결과 보존.

전체 저장소 테스트 **369 passed**. build/verify에서 기존 보고서·UI·README 수치의 일치를 확인했다. 369는 이번 전체 테스트 수이며, 별도 분석 결과인 클릭 정책별 분류 변경369건과 의미가 다르다.

## 실행 방법

저장소 최상위, requirements가 설치된 Python 환경에서 실행한다. CSV는 앞선 [분석표 재현](applicant-mart.md#재현)으로 만들거나 실제 저장된 파일 경로를 사용한다.

```bash
python evidence/applicant/run_aggregate.py --mart work/applicant/mart.csv --sql evidence/applicant/aggregate.sql --output work/applicant/activity-groups.json
python -m pytest -q tests/test_applicant_aggregate.py
```

위 CSV 경로는 예시다. 존재하지 않으면 본인 장치의 실제 경로로 바꾼다. 출력 JSON의 overall과 rows를 확인하며, 입력 학습자 CSV는 공개하지 않는다. 재현 안내는 이번 첨부와 함께 지원자의 로컬 실행 출력을 수신했다는 뜻이 아니다.

## 역할과 완료 범위

지원자는 두 구현 파일을 제출했다. Codex는 계약 안내·제출 원본 보존·검사 작성·실행·실제 자료 대조·문서화·저장소 반영을 수행했다. 이번 첨부에는 별도 참고·도움 설명이나 로컬 실행 출력이 없으므로 추가 설명·실행 경험을 추정하지 않는다.

이번 **기술 집계 모듈은 완료**했다. CSV 형식·집계 일치가 원천 로그의 완전성이나 실제 재방문 개선을 보장하지는 않는다. 신뢰구간·시기 분리·콘텐츠/클릭 민감도와 전체 구현의 후속 범위는 [기존 구현 계약](independent-implementation-brief.md)에 따라 구분한다. 완료한 SQL 실습·v2 실측을 재요구하지 않는다.
