## 제출 코드와 검토 결과

- manifest/원본 검사가 실패하면 DuckDB를 열기 전에 종료한다. 없는 DB가 생성되지 않고 기존 DB의 바이트·수정 시각도 유지되는지 검사했다.
- 성공 시 파일 이름에 대응하는 7개 테이블을 하나의 트랜잭션에서 생성·교체한다. 각 테이블 행 수를 출력하고 종료 코드 0으로 끝낸다.
- 마지막 CSV의 해시는 맞지만 내용이 파싱 불가능한 사례를 만들어, 앞서 처리한 테이블 변경까지 롤백하는지 검사했다. 기존 DB에서는 7개 이전 테이블과 별도 테이블이 보존됐고, 새 DB에서는 부분 적재된 테이블이 남지 않았다. 새 빈 DB 파일까지 삭제하는 기능은 아니다.
- 동일 자료 재실행은 추가 적재가 아닌 교체여서 행 수가 늘지 않았다. 성공 시 지정한 7개 테이블을 교체하므로 전용 출력 DB를 사용한다. 그 밖의 테이블은 보존됐다.
- 공백·작은따옴표가 있는 경로, 빈 값/`?`의 NULL 변환, DB 연결 실패의 비정상 종료도 확인했다.

Codex가 임시 자료와 임시 DB로 작성한 검사 **11개 통과**. 원본 입력 파일은 검사 전후 동일했다. SQL 경계값 전체를 검사한 것은 아니며 적재 다음 단계의 의미·키·날짜 품질 검사는 별도로 필요하다.

## 실제 공개 원본 대조

고정 manifest와 실제 OULAD CSV 7개를 별도 임시 DB에 적재했다. `csv.reader`로 각 원본의 헤더를 제외한 행을 독립 계산해 DuckDB의 `COUNT(*)`와 대조했다. 기존 운영 SQL을 가져다 기준값으로 쓰지 않았다.

| 테이블 | DuckDB 행 수 | 독립 CSV 행 수 |
|---|---:|---:|
| assessments | 206 | 206 |
| courses | 22 | 22 |
| studentAssessment | 173,912 | 173,912 |
| studentInfo | 32,593 | 32,593 |
| studentRegistration | 32,593 | 32,593 |
| studentVle | 10,655,280 | 10,655,280 |
| vle | 6,364 | 6,364 |

일곱 테이블 모두 일치, 종료 코드 0. 실행 전후 실제 CSV의 해시·수정 시각도 같다. 검토용 DB는 임시 폴더에서 생성하고 검사 후 제거했다. 실제 원본·기존 분석 DB·공개 데모를 변경하지 않았다.

## 작은 표현 개선점

DB 연결 자체가 실패한 경우에도 공통 예외 메시지에 `트랜잭션 롤백`이 표시된다. 이때는 트랜잭션이 시작되지 않았을 수 있으므로 실제로 롤백했다는 증거로 읽으면 안 된다. 실패 종료 동작은 정상이고, 요구한 네 가지 적재 동작을 막는 결함은 아니다. 연결 실패와 적재 중 실패의 문구를 분리하면 더 정확해진다. 제출 코드는 고치지 않고 이 의견을 남긴다.

## 역할·완료 범위

지원자는 Python 적재 파일을 제출했다. 이번 첨부에는 별도의 참고 자료·도움 설명이나 본인 로컬 실행 출력이 없었다. 이를 무도움 작성의 인증이나 지원자의 실행 완료 보고로 대신 쓰지 않는다. Codex는 제출본 보존, 테스트 작성, 실제 원본 적재·독립 행 수 대조, 검토 기록·커밋을 담당했다.

첫 원본 검증 모듈과 이번 적재 모듈의 제출·기능 검토는 완료했다. 앞선 SQL 직접 작성·손계산·판단과 v2 사람 실측도 완료 상태를 유지한다. 의미를 검증하는 SQL·통계·운영·UI·배포까지 전체 구현이 완료된 것은 아니며 [선택한 전체 범위](independent-implementation-brief.md)에 따라 이어간다.
